# 退学 KTV 点歌台

## 设计主张

以音乐内容为主角：封面提供色彩，背景和操作区保持中性。首页按「搜索 → 歌手 → 曲库」排列，去掉拟物唱机、装饰口号与混用的标题字体；搜索时只留下搜索结果。曲库保留清晰分列和直接点歌，待唱列表及底部播放器不过度强调。播放页仍让 MV 占据主要位置，标题下方显示歌手署名，不用歌词校对标记替代歌曲信息；诊断仍保存在任务结果中。

## 视觉系统

- 参考：[网易云音乐官方桌面截图](https://apps.apple.com/cn/app/id944848654?mt=12)。借鉴封面优先、内容分组、中性背景与单一强调色，不照搬其频道和运营内容。
- 日间颜色：背景 `#ffffff`，次级表面 `#f5f5f7`，正文 `#25252b`，次级文字 `#6d6d77`。主按钮和强调文字恢复红色 `#cc3045`，按钮文字为白色，弱强调表面使用 `#fceef0`。强调色只用于搜索、播放、点歌及少量当前位置；封面保留原色，不对整页染色。
- 夜间颜色：参考网易云深色界面的[炭灰分层](https://www.xiaoyisysreset.com/soft/bing/appid/103466312)，具体色值为余音适配。背景 `#202022`、次级表面 `#29292d`、选中与抬升表面 `#333338`，正文柔白 `#e5e5e8`、次级文字 `#aaaab3`。主按钮与强调文字采用字幕同款琥珀黄 `#e59a24`，按钮文字 `#241b0d`，柔和强调底色 `#352c21`；不增加大面积彩色、渐变或封面滤镜。全屏复用夜间 token；错误提示保留红色语义。
- 字体：统一系统黑体，用字号、字重和灰度分层，不混用装饰字体；数字等宽。设计 token 在 `web/style.css` 的 `:root` 中。 品牌字标的「退学」与 KTV 使用相近字号（桌面 21 / 20 px，手机 20 / 19 px），统一 600 字重、轻微字距和基线，作为一个完整名称显示。保留 44 px 首页点击区和稳定的导航位置。
- 布局：搜索属于点歌台内容区，滚动时仍可使用。歌手栏动态选取十二位已有可唱歌曲的歌手，各尺寸均可横向滑动；桌面和平板每屏约六位，手机每屏约三位；圆形代表作封面和歌手署名构成一个点击入口。曲库使用紧凑列表，分隔线低对比度。桌面各页共用最大 1200 px 的固定框架，其中主内容最大 832 px、待唱区 272 px，两区间隔 32 px；需要放大 MV 时使用全屏。桌面右侧固定歌单，底部常驻播放器；1100 px 以下收起侧栏，通过导航切换内容；iPad 保留播放，手机只保留点歌和待唱。
- 动效：轻微悬停与准备状态指示，尊重减少动态效果偏好；不增加唱片旋转、逐帧动画或播放器计时器。
- 可访问性：常用按钮保留 44 px 点击区、中文名称和键盘焦点；主要正文、次级文字和主按钮配色保持可读对比度。空格暂停、N 下一首、F 全屏，输入时不截获快捷键。

## 跨屏构图规则

1. **保留内容的视觉分量。** 手机的封面是内容主体，桌面不能把它缩成图标再把行宽撑满。用合适的内容宽度维持图片、署名、操作的比例，而不是只缩字号或封面。
2. **完整单元一起排。** 同一位歌手的图片和署名保持接近；歌曲列表的封面、歌名与点歌入口按行对齐。列间留白分开不同内容。
3. **空白放在组与组之间。** 大屏多出的空间优先留在内容外围和任务区之间；不把所有 `fr` 列无限拉宽。搜索、封面栏和曲库共用主区边缘。
4. **用不同密度表达不同任务。** 封面栏适合浏览，曲库适合逐行选择，待唱负责安排顺序。保留图片与列表的节奏差，不能将所有区域都压成同样的小字列表。
5. **主次区域有归属。** 待唱在辅助表面内成组，主内容使用页面底色；当前条目通过表面明度区分。页头和播放器与内容边缘对齐，主题强调色只用于主要操作。
6. **常驻框架的位置稳定。** 同一窗口内切换点歌台与播放页，Logo、导航按钮、队列和底部播放控件的位置、尺寸保持不变。内容适配共有区域；只有显式进入全屏或改变窗口尺寸才重新布局，不能把页面内容的宽度需求传给全局框架。

验收同时看手机、平板及宽屏的完整页面，并检查搜索、长歌名、长待唱／已唱列表。必须在同一窗口内来回切页，对比公共控件的实际位置；单页截图不能证明切换稳定。一次修改只影响目标断点，不破坏已经确认的布局。

## 行为

右上角月亮／太阳按钮直接切换日间和夜间；未手动选择时跟随系统浅色／深色外观，并随系统切换即时更新；手动选择后优先使用当前浏览器保存的偏好，同源标签页同步，其他设备各自选择。主题在页面绘制前恢复，避免刷新先闪白；切换只更新颜色，不重载页面、不改变导航、选曲、播放进度或音量。两种主题使用相同布局与点击区域。

一个共享房间，预处理队列与播放顺序分别维护。插队调整尚未开始的准备任务，不中断正在处理或播放的歌曲。下一首没有准备好时停留等待，可主动跳过。已点列表在服务端持久化；正常关闭服务时暂停播放。

右侧歌单顶部为「待唱」「已唱」两个 tab，分别显示数量。待唱保留当前歌曲、等待与准备中的所有条目。每行用小封面、歌名、歌手与必要状态展示，置顶和移除始终显示在歌曲下方，单击即可操作，不在每首歌上重复提供开唱按钮。置顶放到本机正在唱的歌曲之后，没有在唱的歌时放到第一；只有尚未开始演唱的空闲预选跟随队首，暂停中的演唱保留曲目、位置和调号；已到目标位置和正在唱的歌曲禁用置顶，不额外占用标题右侧空间；准备失败仍直接展示原因与重试。歌单状态只表达准备进度和错误，不显示「已暂停／正在播放」；播放状态由播放按钮和当前歌曲标记表达。已唱按演唱先后倒序显示，歌名和歌手上方不堆叠状态；时间与「再点」位于下面同一操作行。顶部提供本地歌名／歌手搜索，筛选不改变倒序和重复演唱记录。「再点」只加入队尾，保留当前 tab 与搜索词，方便继续选择。Tab 和搜索词随页面历史恢复，演唱记录以服务端持久数据为准。加载或倒计时阶段跳过的歌曲不冒充已唱，浏览历史不刷新媒体 LRU。

进度通过 SSE 推送，初始连接及重连收到完整快照。处理进程通过标准输出事件汇报阶段，不定时读进度文件。客户端不会轮询状态。

「重试」与置顶、移除放在同一操作行，不嵌在长错误文案中；等待自动重试时仍可手动操作。已有成品不提供「重新准备」入口。错误文案留在状态区，播放页错误下方也保留重试按钮。处理中的任务不提供重复提交入口。

按过播放的浏览器保留接唱意图，歌单暂空不会清除它。SSE 推送待唱歌曲就绪后自动进入播放页并接唱；当前已在唱则继续，尚未就绪则选第一首可唱的。主动暂停取消接唱，点歌本身不把其他设备变成播放器。换歌复用已经启用的音频上下文；若移动浏览器在两首之间暂停了上下文，下一首调度前自动恢复，不能要求每首重新点播放。播放意图由同一浏览器的标签页共享，浏览器尚未允许声音或媒体未就绪时不启动时钟。

准备进度放在歌曲状态位置：一行步骤名称与百分比，下面一条 3 px 暖金进度条。并行步骤各占一行，播放页复用同一种展示。歌手署名同一行的右侧显示次级文字「已用时 m:ss」，处理步骤与百分比留在下面；窄屏时长文字省略显示，计时不换行，按服务端记录的本次任务开始时间累计，每秒仅更新计时文字；排队时不显示，切换步骤与刷新不归零，结束后移除。没有可靠总量时用不定量进度条，不显示猜测的百分比；无需额外解释文案。渲染完成后的封装、校验仍显示各自状态，直到成品实际可用。

本地曲库只展示已完成且成品文件齐全的歌曲，首页全部、语言分类和本地搜索共用同一筛选规则。点歌后准备中的歌曲显示在待唱队列，完成后才进入曲库；缓存回收后立即从本地曲库移除，保留已唱记录和来源元数据。旧版「可直接唱」筛选恢复为「全部」，避免两个内容相同的入口。本地曲库每页12首，标题右侧和列表底部提供上一页、页码选择和下一页；单页时隐藏分页控件。页码按标签页随浏览器历史恢复，切换筛选或关键词回到第一页；后台准备进度不重置当前页，歌曲减少时收敛到最后有效页。分页只限制当前显示数量，保留全部歌曲与原顺序，在线搜索仍按原有方式下拉加载。曲库、歌单与播放页共享 SSE 快照；只更新进度时保留按钮节点和键盘焦点，不重建歌曲行。

来源封面与歌曲元数据一起持久化，搜索点歌或下载取得图片地址后立即显示，不能等待音轨与 MV 完成。完成后优先显示本地封面，重试和局部进度更新保留已有图片；沿用现有封面尺寸与裁切，不改变歌曲行布局。歌手页按实际可用的歌曲、视频、发行栏目展示，分别使用「热门歌曲」「歌手视频」「歌手作品」标题。

曲库、搜索结果、预览和链接点歌使用同一套点歌状态。提交中暂时禁用按钮；成功后原位显示禁用的「已点」和「第 N 首」，位置以房间实际队列为准，随 SSE 调序、切歌或移除更新。来源 URL 的等价形式按同一视频识别，不靠歌名合并不同录音。点歌只加入队列，不改变选曲、顺序或播放；反馈中的「查看待唱」只导航到队列。播放统一使用播放器的播放按钮。失败后恢复点歌；已在待唱里的歌曲避免重复提交，需要再次演唱时仍可从「已唱」主动再点。

共享歌单、准备状态与演唱历史由服务端快照同步。浏览器历史只保存本标签页的搜索、导航和筛选；选曲、播放意图、进度、混音、升降调由同源 localStorage 共享，不缓存共享歌单。只有当前拥有播放权的标签页发声和保存进度；每次移交使用唯一会话标识，异步播放回调须复核所有权，不能靠各标签自增的 revision 仲裁。切歌的结束命令在本机持久保留，服务器确认后才清除；未确认条目标注“等待同步移除”，断线后指数退避补发，已唱记录按条目 ID 幂等处理。另一个标签操作播放控件时接管，旧回调不能覆盖新选曲。返回后台页面先同步播放会话与最新歌单；暂停或恢复的已删除选曲回到待唱队首，其他设备正在唱的歌曲仍可继续。网页整体增益固定 100%，不提供总音量或静音控件；清除旧版保存的总音量，由设备音量键控制响度。同一个房间 revision 内也可能发生任务进度、元数据或缓存更新，因此迟到的响应还需按 server_time 拒绝，不能把新进度恢复成旧状态。网页普通点歌在服务端按来源检查是否已入队，主动再点则明确允许重复。共享搜索缓存只复用相同关键词／类型／分页的元数据；各标签页的当前查询与取消请求独立。

状态推送在房间空闲时仍发送心跳；连接彻底关闭或连续三个心跳周期没有数据时，重新订阅完整快照，不轮询房间。网络恢复与页面回到前台也重新订阅。页面离开时释放播放权；原页面恢复时，仅在释放的会话未被其他标签接替时取回播放权，保留连续接唱或主动暂停的意图，不能抢回新会话的声音。

播放器使用一个 AudioContext 同时调度背景音乐、伴唱、主唱的三个分段解码音轨；MV 静音播放并跟随同一时钟。人声切换只调节增益，不重新载入视频。首次播放需要用户点击以启用浏览器声音。桌面和平板在用户点击的当前设备播放；手机只点歌，不接管其他设备，不共享播放时钟。

音轨、画面、进度、缓冲和结束判断都以同一个 `AudioContext.currentTime` 为基准；画面侧扣除浏览器报告的 `baseLatency` 和 `outputLatency`。不使用独立的 `getOutputTimestamp()` 推进播放：实际 iPad 上该接口可能返回近乎冻结的时间，导致声音正常、视频永远等待起播。未提供的设备延迟按零处理，因此未知的硬件延迟不作精确同步保证。变调处理延迟单独保留，不改写歌词时间戳。

开头的三点准备提示透明叠在已加载的第一帧上，保留封面、歌曲信息与白色预读歌词，不用黑底遮住画面。仍保留完整四秒提示，音轨与视频在歌曲零点一起开始。

播放文件地址带各自的内容哈希。同一首歌修复字幕或音轨后，页面按实际文件版本重新加载并保留本机播放位置与混音；只更新歌名、封面或其他状态不会重载正在播放的音视频。过期版本的分段请求不能读取新版本的字节，预览与正式播放共用同一版本地址。

开播前先等待目标位置的画面解码完成，并确认浏览器原生视频播放能启动，再安排三轨音频；原生视频在倒计时和音频处理延迟期间暂停，仍在设备输出时钟到达起点时继续。视频保持原生 1 倍速：WebKit 改速会同时暂停解码和视频时钟，随后针对新偏差再次改速会形成卡顿循环。小幅时间戳差异不触发调速；`readyState` 短暂下降但画面仍推进时保持声音连续。明显失步或实际停止推进时冻结共同播放时钟，针对固定位置完成加载后恢复，不能不断跳转追赶仍在前进的声音。视频启动拒绝或超时会停止播放并显示重试入口；旧播放请求的回调不能影响新歌。尚未启用声音的页面不跟随其他设备的时钟反复跳转预览。三条音轨的时钟和速度始终不变。

正常播放不运行逐帧 JavaScript 循环。音频由 AudioContext 提前调度，控制栏和媒体检查每 100 ms 更新一次；开播时额外按声音实际起点唤醒，暂停、结束和离开预览后停止计时。只有原生视频时钟异常时，才请求一次呈现帧确认，避免将 WebKit 偶发的旧时间误判成失步；确认等待有界，时钟自行恢复就取消检查，旧歌曲的回调不能影响新歌。

加载歌曲时预载视频画面，并行解码当前 8 秒片段的三条音轨；当前段全部可用后即可开唱，不等待整首下载。后台从当前段继续下载到曲尾，再补齐前面的片段；压缩音频留在当前歌曲的浏览器缓存中，定位或重唱可复用。解码仍只保留当前段及随后约 24 秒，避免将整首展开成大量 PCM。下载和解码的进度彼此独立。临时网络错误、超时或服务器错误最多尝试三次，尊重 Retry-After；切歌取消旧下载，认证及文件错误不循环重试。仍未到齐时先播完已有音频，再冻结共同播放时钟，齐备后恢复。升降调处理器在用户点击并启用声音后初始化，不阻塞首次加载；原调和暂停时跳过变调 DSP。

普通视图将歌曲、播放控制、主唱与升降调分组。封面和署名保持在一起，播放键为主要视觉焦点；主唱与升降调各自使用浅灰底的紧凑控制组，百分比和调号采用中性色，避免所有数字都争抢强调色。全屏复用相同的控件顺序和分组，只切换为暗色表面。伴奏和伴唱始终开启，不提供多余的模式与三轨滑杆；每次 5 个百分点的主唱加减按钮只调节原唱主旋律，不能重载音频或改变播放进度。恢复旧设置时将伴奏和伴唱设为 100%，主唱保留已有百分比，避免隐藏控件后留下关掉的伴奏。两个升降调按钮每次改变一个半音，中间只显示当前调号，不再是第三个按钮。

手机宽度不超过 760 px，以及宽度不超过 1000 px、高度不超过 500 px 的横屏小窗口，只显示点歌台和待唱。移除正在播放导航、播放器、底栏和缓存管理控件，页面底部不保留播放器空白。手机不取得音频所有权、不恢复播放意图、不发送播放快捷键或结束事件，也不加载预览；歌曲封面和标题直接点歌，已点歌曲跳到待唱位置，队列中的标题和封面为静态信息。进入手机布局时停止并释放本标签页播放，不能改写其他标签页的播放；返回大屏需要手动开唱。该规则属于响应式界面行为，不是账号权限边界。

手机列表参考[网易云音乐官方 iPhone 截图](https://apps.apple.com/cn/app/id590338362)：44 px 封面、两行歌名／歌手、右侧点歌组成一个 68 px 高的单元；窄布局隐藏找 MV，将宽度留给歌曲信息。搜索结果的播放量与时长在歌手后面并列，以万／亿缩写播放量，数字完整显示；没有播放量的数据不占位，不额外增加一行。歌手文本与歌名共用点击区，常用动作至少 44 × 44 px；长文字省略，专辑等必要类型标签仍显示。语言分类横向滚动，数量与标签不拆行；准备和失败状态允许按内容增高。

已唱列表与首页最近唱过复用同一来源去重：只显示每个录音的最后一次演唱，并按演唱时间倒序排列。计数与搜索以去重后的歌曲为准；同名的不同录音不合并，历史记录仍保留。

全屏将同一个底部控制面板移入播放器容器，退出时移回原位，保留事件监听器与状态。底部提供播放／暂停、重唱、下一首、主唱音量、升降调和唯一的播放进度条；隐藏歌曲元数据。主唱名称是「主唱：开／关」按钮，关闭归零、开启恢复最近一次非零百分比（首次 100%），记忆值随浏览器播放会话保存和跨标签页同步；旁边继续显示百分比；主唱关闭时加减按钮同时禁用，必须通过开关恢复后才能调节，开启且达到 100% 时只禁用增加方向；全屏只显示播放进度滑杆，避免 iPad 上误触混淆。控件占据视频下方的独立空间，不压住歌词。全屏宽度大于 860 px 时，播放按钮与进度在左列，主唱和调号在右列，两组间隔 48 px；进度条不横跨右列，避免误点主唱时跳进度。窄屏依次为进度、播放、声音控制三行，行间保留 16 px，播放行将调节组与进度条隔开。普通窄屏控制栏同样保留 12 px 行距，按内容宽度收窄布局，避免新增文字挤到相邻控件。触屏主要按钮至少 44 px 高，缩略图、歌名、歌手和缓存入口也保留足够点击区。

导航只改变页面，不重启歌曲。左上角退学 KTV始终回主页面、清空搜索并聚焦输入；浏览器后退仍可回到先前的搜索。当前曲目的封面／歌名和底部歌曲区域直接展示播放页；其他歌曲继续预览。显式导航滚到页面顶部，历史恢复与窗口大小变化保留各自的滚动位置。

首页「本地曲库」只展示音轨和视频均可播放的成品，使用「全部」和语言分类筛选。歌手栏放在搜索与曲库之间，点击头像或姓名后直接展开对应歌手页的作品列表，复用歌手搜索的自动展开路径。

页面文案只保留名称、操作和有用的状态。不要添加装饰英文、口号、缓存／预处理流程说明或重复的操作指引；空状态用短句，空间不足时才显示处理建议，歌词复核状态只用简短标签。

没有可显示字幕时标为「歌词暂缺」，已有歌词但对齐仍待复核时标为「歌词待校对」，不能把缺词说成只是校对问题。新下载和为已有音频补画面时最多选择 720p，音频仍独立选择最佳可用音轨；已有缓存继续复用。

缓存用量放在歌单底部的折叠区，平时只展示已用／上限，展开后才显示容量设置和空间不足的处理提示。统计范围写入使用文档。缓存变化复用房间 SSE，音量只在本机更新，不增加浏览器轮询。

选歌围绕两条路径：知道歌名时查单曲，只知道想唱谁时找歌手，再浏览热门歌曲。默认「综合」把原始关键词交给 YouTube Music，不加歌曲类型或标题匹配限制，保留原站返回的歌曲、专辑、歌手等结果；专辑可进入曲目列表逐首点歌。使用 YouTube Music 中文元数据，中文歌手显示平台提供的中文名，不自行翻译或拼音化；「歌手」搜索直接展开平台首个结果的曲目，沿用紧凑的头像、姓名和歌曲列表，不先展示必须点击的大卡片。有其他候选或下一页时，姓名下方提供低强调的「其他歌手」入口，候选列表保留头像、姓名及原生分页；没有其他候选时不显示入口。单曲歌手署名也可进入热门列表。沿用中性底色与系统字体，主操作使用同一种强调色。歌曲、歌手热门和视频结果使用带表头的列表，歌名与封面、歌手（视频为频道）、专辑、播放量、时长分别成列；「点歌」与「找 MV」各占独立操作列，使用一致的高度和内边距，点歌以底色强调、找 MV 使用次级描边，两个按钮的宽度随内容收紧，不撑满操作列；两个按钮均保留左右各 12 px 的框内留白；点歌成功后原位显示禁用的「已点」与「第 N 首」，不重复提交或切歌，视频列表的后一列仍为来源链接。歌名下方仅保留版本、专辑类型等识别信息及必要的准备进度、失败提示；曲库、搜索和待唱列表不显示「可直接唱」「待补视频」等静态就绪标签。缺失信息显示短横线；本地曲库与本地搜索复用同一种歌曲行，不展示尚无数据的播放量和专辑列，仍保留独立的「点歌」「找 MV」。依据列表实际宽度收起专辑列，手机将歌手放在歌名下方，省去播放量，时长与歌手同行，右侧只保留点歌，隐藏找 MV，不横向挤压或溢出。已加载数量与标题同行，搜索类型与排序紧邻列表。

综合搜索分为上方「曲库里的歌」和下方「搜索结果」两个独立区域，本地没有匹配时整段隐藏；线上默认先歌曲、再专辑、再其他类型，各类保留平台相关度或歌手热门顺序，歌曲中标题明确标注 Live／现场版的结果靠后；专辑内保留曲目顺序；用户可选择已加载结果按真实播放量、已准备优先或歌名排序。没有播放量就禁用该选项，不能补零、编造热度或将 YouTube 热门顺序标为 KTV 点唱榜。保留平台返回的全部结果和不同版本。歌手首次展开遵循平台顺序，不凭搜索词或译名猜身份；其他结果可随时切换。自动展开不增加浏览器历史层级，返回不落回中转页；显式打开候选列表时保留该列表，刷新不强制再次展开。

「YouTube 视频」保留每一页的完整结果；默认仅将明确标注的现场版后置，不按关键词、认证、类型额外过滤，不限制为 3 条，不请求B站；单曲的「找 MV」进入该搜索。封面点开预览；预览提供原站链接。输入停顿或回车触发，中文组词期间暂停请求，输入或搜索类型变化立即使旧结果失效。预览关闭即移除播放器，弹窗和排序控件内不响应播放快捷键。搜索标题仅作准备阶段的临时名称。

「下一首」在桌面、平板普通页面和全屏的同一个底部控制栏提供。不添加确认弹窗；请求期间禁用按钮，携带点击时的歌曲 ID 防止过期事件重复切歌。

「综合」复用曲库列表在上方展示有完整成品的本地匹配项，只剩元数据、缺少视频或仍在准备的歌曲不计入本地匹配；不等待线上请求；线上失败时仍可点本地歌曲。本地和线上各自计数、分页，下面的搜索结果保留完整的线上列表与排序，即使两处包含相同来源也不合并。追加分页、刷新恢复和本地状态更新保持这一布局，本地没有匹配时不显示标题、计数或空状态。「本地曲库」仍可单独查看已有曲库，其他搜索来源保持各自结果。预览复用本地缓存 MV，点歌复用任务。搜索期间收起历史推荐和无关曲库歌曲。

专辑结果使用明确的「专辑」标签和「查看专辑」，进入后再逐首点歌；不能将专辑自动当成其中一首歌。「返回上一级」与浏览器前进／后退恢复原来的列表、排序和滚动位置。关键词、语言分类、当前页面、已加载结果和分页位置随浏览器历史保存，刷新后恢复；共享歌单继续以服务端 SSE 为准，本机进度独立恢复。

歌曲、歌手、歌手热门列表和视频搜索均随下拉按需加载下一页，不设置总结果截断。顶部只显示已加载数量，末尾保留 44 px 高的手动加载／重试按钮与简短状态。追加结果保留现有歌曲行、图片和键盘焦点；换词或切换类型时作废旧请求。到达平台最后一页显示「已经到底了」。分页失败保留已加载歌曲，不自动重试风暴；过期时提供重新搜索。播放量、已准备优先、歌名只排序已加载结果，默认先歌曲再专辑，各类保留平台顺序，并将歌曲中明确标注的现场版后置。

首页「歌手」从现有可唱曲库中按保存的歌手署名去重，默认先选八位有华语歌曲、四位有英语歌曲的歌手，各组优先曲库歌曲数多的，同数保持曲库顺序；按歌曲已保存的演唱语言选取，不按姓名文字猜测，同一署名只显示一次；某组不足时从其余可唱曲库歌手补齐十二位；不依赖演唱历史，不拆分合作署名或猜测平台身份。图片复用其代表作封面，不额外请求头像；歌曲数仅用于选取歌手，不在卡片中显示。点击头像或姓名直接展开该署名的歌手页；标题右侧「更多」切换为歌手搜索并聚焦顶部输入框，提示文字改为「搜索歌手」。搜索期间隐藏歌手栏，返回恢复。空曲库或没有歌手信息时隐藏这一栏，已唱记录仍在原来的「已唱」tab 中。

## 美学验收

曲库语言分类在「华语」后独立显示「粤语」，不把粤语重复归入其他语言。全部与每个语言分类旁用次级灰色等宽数字显示可直接唱的歌曲总数，与实际分类筛选使用同一规则，不受当前分页或选中分类影响；空分类显示 0，随曲库快照更新。分类依据保存的演唱语言，不能用繁体字或歌手籍贯猜测；汉字文本无法细分时，在歌曲准备阶段补充音频语言证据。窄屏按空间换行，标签与数字保持同一行，按钮大小与其余语言保持一致。

每次 UI 修改都需按 `AGENTS.md` 完成美学检查，保留整页和局部的实际截图，并写明判断依据；自动化功能测试不能代替这个步骤。当前底栏参考 [Refactoring UI 的公开留白章节](https://refactoring-ui.nyc3.cdn.digitaloceanspaces.com/Refactoring%20UI%20-%20Start%20with%20too%20much%20white%20space.pdf)及 [The Non-Designer’s Design Book 的公开样章](https://www.peachpit.com/content/images/9780133966152/samplepages/9780133966152.pdf)，落实相关元素分组、重复样式的一致性、明确视觉焦点和克制的边框使用。

## 信息层级与元数据

综合／歌手属于搜索内容，YouTube 视频／本地曲库作为另外的来源入口分组；不丢弃上游返回的结果。空专辑列不给固定宽度，歌名优先；手机省去播放量，保留歌手同行的时长，右侧只保留点歌。已有元数据按视频 ID 合并，缺失字段不能抹去歌手页提供的播放量。播放页去掉装饰唱片与重复歌手署名，普通视图只保留一处下一首，完整画面不裁切。
