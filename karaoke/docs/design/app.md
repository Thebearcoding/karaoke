# 余音点歌台

## 设计主张

像夜里一间安静的小唱片店：暗橄榄色背景、暖白文字、少量琥珀金。点歌是第一入口，歌单始终可见，切换到播放页后让 MV 占据主要位置。沿用已经选定的暖金跟唱字幕，不让网页装饰争夺注意力。通过封面、留白和文字层次建立气质，状态信息保持短小。

## 视觉系统

- 颜色：背景 `#111312`，表面 `#181b19`，正文 `#f0f0ec`，次级文字 `#a6aaa4`，金色 `#dfb56f`，就绪 `#a6c39b`。
- 字体：标题和控件统一使用系统黑体，通过字号、字重与留白分层；数字等宽。设计 token 在 `web/style.css` 的 `:root` 中。
- 布局：顶部常驻紧凑搜索栏，滚动时仍可搜索；桌面为点歌／播放主区＋固定宽度歌单，底部常驻播放控制。900 px 以下通过导航切换三个主区，为 iPad 竖屏和手机保留完整列表宽度。
- 动效：轻微悬停与准备状态指示，尊重减少动态效果偏好；播放器字幕继续使用已经对齐的 MV，不追加时间偏移。
- 可访问性：按钮有中文名称、键盘焦点、可见状态文字；图标按钮保留可访问名称。空格暂停、N 下一首、F 全屏，输入时不截获快捷键。

## 行为

一个共享房间，预处理队列与播放顺序分别维护。插队调整尚未开始的准备任务，不中断正在处理或播放的歌曲。下一首没有准备好时停留等待，可主动跳过。已点列表在服务端持久化；正常关闭服务时暂停播放。

右侧歌单顶部为「待唱」「已唱」两个 tab，分别显示数量。待唱保留当前歌曲、等待与准备中的所有条目。每行用小封面、歌名、歌手与必要状态展示，调序、现在唱和移除收在常驻的更多操作中，触屏无需悬停；准备失败仍直接展示原因与重试。已唱按演唱先后倒序显示，歌名和歌手上方不堆叠状态；时间与「再点」位于下面同一操作行。顶部提供本地歌名／歌手搜索，筛选不改变倒序和重复演唱记录。「再点」只加入队尾，保留当前 tab 与搜索词，方便继续选择。Tab 和搜索词随页面历史恢复，演唱记录以服务端持久数据为准。加载或倒计时阶段跳过的歌曲不冒充已唱，浏览历史不刷新媒体 LRU。

进度通过 SSE 推送，初始连接及重连收到完整快照。处理进程通过标准输出事件汇报阶段，不定时读进度文件。客户端不会轮询状态。

准备进度放在歌曲状态位置：一行步骤名称与百分比，下面一条 3 px 暖金进度条。并行步骤各占一行，播放页复用同一种展示。歌手署名同一行的右侧显示次级文字「已用时 m:ss」，处理步骤与百分比留在下面；窄屏时长文字省略显示，计时不换行，按服务端记录的本次任务开始时间累计，每秒仅更新计时文字；排队时不显示，切换步骤与刷新不归零，结束后移除。没有可靠总量时用不定量进度条，不显示猜测的百分比；无需额外解释文案。渲染完成后的封装、校验仍显示各自状态，直到成品实际可用。

点歌后曲库立即出现该歌曲，语言分类随音频证据更新，不能把排队中的歌曲标为「已准备」。曲库、歌单与播放页共享 SSE 快照；只更新进度时保留按钮节点和键盘焦点，不重建歌曲行。

来源封面与歌曲元数据一起持久化，搜索点歌或下载取得图片地址后立即显示，不能等待音轨与 MV 完成。完成后优先显示本地封面，重试和局部进度更新保留已有图片；沿用现有封面尺寸与裁切，不改变歌曲行布局。歌手页按实际可用的歌曲、视频、发行栏目展示，分别使用「热门歌曲」「歌手视频」「歌手作品」标题。

曲库、搜索结果、预览和链接点歌使用同一套点歌状态。提交中暂时禁用按钮；成功后原位显示「已加入 · 第 N 首」，位置以房间实际队列为准，随 SSE 调序、切歌或移除更新。来源 URL 的等价形式按同一视频识别，不靠歌名合并不同录音。失败后恢复点歌；已在待唱里的歌曲避免重复提交，需要再次演唱时仍可从「已唱」主动再点。

房间状态只由服务端快照同步；浏览器历史只保存本标签页的搜索、导航和筛选，不缓存房间歌单或播放位置作为恢复来源。本机总音量保存在 sessionStorage，刷新可恢复，前进／后退不改变音量。同一个房间 revision 内也可能发生任务进度、元数据或缓存更新，因此迟到的响应还需按 server_time 拒绝，不能把新进度恢复成旧状态。网页普通点歌在服务端按来源检查是否已入队，主动再点则明确允许重复。共享搜索缓存只复用相同关键词／类型／分页的元数据；各标签页的当前查询与取消请求独立。

播放器使用一个 AudioContext 同时调度背景音乐、伴唱、主唱的三个分段解码音轨；MV 静音播放并跟随同一时钟。人声切换只调节增益，不重新载入视频。首次播放需要用户点击以启用浏览器声音。遥控模式控制同一房间但不发声。

开头的三点准备提示透明叠在已加载的第一帧上，保留封面、歌曲信息与白色预读歌词，不用黑底遮住画面。仍保留完整四秒提示，音轨与视频在歌曲零点一起开始。

播放文件地址带各自的内容哈希。同一首歌修复字幕或音轨后，页面按实际文件版本重新加载并保留房间的播放位置与混音；只更新歌名、封面或其他状态不会重载正在播放的音视频。过期版本的分段请求不能读取新版本的字节，预览与正式播放共用同一版本地址。

视频小幅漂移时只微调静音视频的播放速度；明显落后时才跳转，并等待跳转完成和解码稳定，避免逐帧重置解码器。尚未启用声音的页面不跟随其他设备的时钟反复跳转预览。三条音轨的时钟和速度始终不变。

加载歌曲时预载视频画面，并行解码当前 8 秒片段的三条音轨；当前段全部可用后才允许启动播放时钟。升降调处理器在用户点击并启用声音后初始化，不阻塞首次加载，也不让「开始唱」按钮陷入等待点击的循环。原调和暂停时跳过变调 DSP。音频只保留当前段和下一段；分段不足时冻结共同播放时钟，齐备后恢复。

普通窗口底栏将歌曲、播放、模式／升降调、三轨音量四组横向排列，内容最大宽度为 1120 px。歌曲封面、名称和本机总音量放在左侧；播放、重唱、下一首及进度放在一起；人声模式与升降调上下排列，三个声部滑杆独立竖排在最右侧。播放进度不再叠在音量滑杆上方，让几组控件并排共享同一高度。重唱、下一首和调音组去掉重复外框，以文字、灰阶选中背景和留白区分。金色突出播放及正在操作的滑杆，静态滑杆使用 2 px 暖灰轨道和小滑块，实际点击区域保持至少 24 px，触屏增至 32 px。

760 px 以下才换为两列两行：歌曲与播放在上，调音预设与三个竖排滑杆在下；手机的重唱、下一首使用图标并保留可访问名称。三个滑杆始终直接可调，不收进菜单。底栏上下各保留 8 px 内边距，封面使用 40 px；滑杆连续排列，不额外叠加行间空白。触屏仍保留 32 px 滑杆区域和 44 px 播放按钮，不靠缩小触控面积压低高度。底栏实际高度用于页面底部留白及歌单高度，避免遮住内容。全屏时把同一组滑杆移到视频下方，退出后移回调音区，保留监听器与混音数值，不重新载入音频。声音模式作为快捷预设，手动调整的数值跨歌曲保留。

全屏时把同一条播放进度条移到视频下方，显示已播和总时长，支持拖动；退出后移回底部控制栏。复用同一个控件及其播放时钟，避免全屏和普通视图各自维护进度。进度条占据独立空间，不覆盖歌词。

底部控制栏常驻人声模式、升降调、重唱和下一首，在点歌和浏览历史时都能操作。人声模式和升降调使用灰阶选中状态与留白分组，沿用现有房间命令，不重复维护播放器状态。窄屏将调音控件放在播放按钮下一行，全部保留可点击区域。

全屏控制区底部保持紧凑的两行：完整进度条和时间、并排的三个小音量滑杆。人声模式和升降调移到画面右上角，退出后把同一组控件移回底栏，不追加底部控制行。窄屏避开左上角的下一首按钮。

升降调使用小控件 `♭ 原调 ♯`，改变后中间显示有符号半音数，点击中间恢复原调，不在画面内放算法说明。
播放页去掉装饰英文和重复的模式说明。全屏只保留时间与三个声部名称，百分比仅在悬停或键盘调节时显示；滑杆始终提供可访问的名称与当前值。

页面文案只保留名称、操作和有用的状态。不要添加装饰英文、口号、缓存／预处理流程说明或重复的操作指引；空状态用短句，空间不足时才显示处理建议，歌词复核状态只用简短标签。

没有可显示字幕时标为「歌词暂缺」，已有歌词但对齐仍待复核时标为「歌词待校对」，不能把缺词说成只是校对问题。新下载和为已有音频补画面时最多选择 720p，音频仍独立选择最佳可用音轨；已有缓存继续复用。

缓存用量放在歌单底部的折叠区，平时只展示已用／上限，展开后才显示容量设置和空间不足的处理提示。统计范围写入使用文档。缓存和音量变化都复用房间 SSE，不增加浏览器轮询。

选歌围绕两条路径：知道歌名时查单曲，只知道想唱谁时找歌手，再浏览热门歌曲。默认「全部」把原始关键词交给 YouTube Music，不加歌曲类型或标题匹配限制，保留原站返回的歌曲、专辑、歌手等结果；专辑可进入曲目列表逐首点歌。使用 YouTube Music 中文元数据，中文歌手显示平台提供的中文名，不自行翻译或拼音化；「歌手」显示可区分的歌手头像与名称，点击后读取该歌手的热门列表。单曲歌手署名也可进入热门列表。沿用暗橄榄色与系统字体，琥珀色用于播放、进度和少量选中标记。歌曲、歌手热门和视频结果使用带表头的列表，歌名与封面、歌手（视频为频道）、专辑、播放量、时长分别成列；「点歌」与「找 MV」各占独立操作列，共用有底色和边框的按钮样式，两个按钮的宽度随内容收紧，不撑满操作列；两个按钮均保留左右各 10 px 的框内留白；点歌成功后原位显示「已加入 · 第 N 首」并禁用重复点击，视频列表的后一列仍为来源链接。版本和准备状态留在歌名下方。缺失信息显示短横线；本地曲库与本地搜索复用同一种歌曲行，不展示尚无数据的播放量和专辑列，仍保留独立的「点歌」「找 MV」。依据列表实际宽度收起专辑列，窄屏将歌手与播放数据分行对齐，两个操作仍在右侧并列，不横向挤压或溢出。已加载数量与标题同行，搜索类型与排序紧邻列表。

默认排序先歌曲、再专辑、再其他类型，各类保留平台相关度或歌手热门顺序，歌曲中标题明确标注 Live／现场版的结果靠后；专辑内保留曲目顺序；用户可选择已加载结果按真实播放量、已准备优先或歌名排序。没有播放量就禁用该选项，不能补零、编造热度或将 YouTube 热门顺序标为 KTV 点唱榜。保留平台返回的全部结果和不同版本。同名歌手由用户选择，不凭标题猜身份。

「YouTube 视频」保留每一页的完整结果；默认仅将明确标注的现场版后置，不按关键词、认证、类型额外过滤，不限制为 3 条，不请求B站；单曲的「找 MV」进入该搜索。封面点开预览；预览提供原站链接。输入停顿或回车触发，中文组词期间暂停请求，输入或搜索类型变化立即使旧结果失效。预览关闭即移除播放器，弹窗和排序控件内不响应播放快捷键。搜索标题仅作准备阶段的临时名称。

「下一首」使用文字加图标，在底部控制栏和画面左上角提供同一操作，全屏继续保留。不添加确认弹窗，不扩展底部两行控制区；请求期间禁用按钮，携带点击时的歌曲 ID 防止过期事件重复切歌。

「本地」独立查看已有曲库；已准备状态只关联相同来源 URL，不能把其他版本标成已准备。预览复用本地缓存 MV，点歌复用任务。搜索期间收起首页曲库与历史推荐。

专辑结果使用明确的「专辑」标签和「查看专辑」，进入后再逐首点歌；不能将专辑自动当成其中一首歌。「返回上一级」与浏览器前进／后退恢复原来的列表、排序和滚动位置。关键词、语言分类、当前页面、已加载结果和分页位置随浏览器历史保存，刷新后恢复；房间播放状态继续以服务端 SSE 为准。

歌曲、歌手、歌手热门列表和视频搜索均随下拉按需加载下一页，不设置总结果截断。顶部只显示已加载数量，末尾保留 44 px 高的手动加载／重试按钮与简短状态。追加结果保留现有歌曲行、图片和键盘焦点；换词或切换类型时作废旧请求。到达平台最后一页显示「已经到底了」。分页失败保留已加载歌曲，不自动重试风暴；过期时提供重新搜索。播放量、已准备优先、歌名只排序已加载结果，默认先歌曲再专辑，各类保留平台顺序，并将歌曲中明确标注的现场版后置。

首页在有演唱历史时展示最多四首「最近唱过」与六位「常唱歌手」。最近歌曲按最后演唱时间倒序，按来源去重；不同录音不会因同名而合并。「常唱歌手」按实际演唱次数排序，同次数按最近演唱时间排序，点击沿用歌手搜索。不猜测平台歌手身份，不请求额外元数据或虚构热度。最近歌曲可直接再点，「全部已唱」进入完整历史；没有历史时隐藏此区。

## 美学验收

每次 UI 修改都需按 `AGENTS.md` 完成美学检查，保留整页和局部的实际截图，并写明判断依据；自动化功能测试不能代替这个步骤。当前底栏参考 [Refactoring UI 的公开留白章节](https://refactoring-ui.nyc3.cdn.digitaloceanspaces.com/Refactoring%20UI%20-%20Start%20with%20too%20much%20white%20space.pdf)及 [The Non-Designer’s Design Book 的公开样章](https://www.peachpit.com/content/images/9780133966152/samplepages/9780133966152.pdf)，落实相关元素分组、重复样式的一致性、明确视觉焦点和克制的边框使用。
