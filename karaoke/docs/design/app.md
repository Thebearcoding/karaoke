# 余音点歌台

## 设计主张

像夜里一间安静的小唱片店：暗橄榄色背景、暖白文字、少量琥珀金。点歌是第一入口，歌单始终可见，切换到播放页后让 MV 占据主要位置。沿用已经选定的暖金跟唱字幕，不让网页装饰争夺注意力。通过封面、留白和文字层次建立气质，状态信息保持短小。播放页标题下方显示已有的歌手署名，不用歌词校对标记替代歌曲信息；诊断仍保存在任务结果中。

## 视觉系统

- 颜色：背景 `#111312`，表面 `#181b19`，正文 `#f0f0ec`，次级文字 `#a6aaa4`，金色 `#dfb56f`，就绪 `#a6c39b`。
- 字体：标题和控件统一使用系统黑体，通过字号、字重与留白分层；数字等宽。设计 token 在 `web/style.css` 的 `:root` 中。
- 布局：搜索栏占据顶部中央的视觉重心，使用更大字号、琥珀色边框与明确的搜索按钮，滚动时仍可搜索；桌面为点歌／播放主区＋固定宽度歌单，底部常驻播放控制。1100 px 以下通过导航切换三个主区，为 iPad 竖屏和手机保留完整列表宽度。
- 动效：轻微悬停与准备状态指示，尊重减少动态效果偏好；播放器字幕继续使用已经对齐的 MV，不追加时间偏移。
- 可访问性：按钮有中文名称、键盘焦点、可见状态文字；图标按钮保留可访问名称。空格暂停、N 下一首、F 全屏，输入时不截获快捷键。

## 行为

一个共享房间，预处理队列与播放顺序分别维护。插队调整尚未开始的准备任务，不中断正在处理或播放的歌曲。下一首没有准备好时停留等待，可主动跳过。已点列表在服务端持久化；正常关闭服务时暂停播放。

右侧歌单顶部为「待唱」「已唱」两个 tab，分别显示数量。待唱保留当前歌曲、等待与准备中的所有条目。每行用小封面、歌名、歌手与必要状态展示，准备完成的歌曲直接提供「开始唱」，上移、下移和移除始终显示在歌曲下方，单击即可操作；首尾不可用的调序按钮禁用，不额外占用标题右侧空间；准备失败仍直接展示原因与重试。已唱按演唱先后倒序显示，歌名和歌手上方不堆叠状态；时间与「再点」位于下面同一操作行。顶部提供本地歌名／歌手搜索，筛选不改变倒序和重复演唱记录。「再点」只加入队尾，保留当前 tab 与搜索词，方便继续选择。Tab 和搜索词随页面历史恢复，演唱记录以服务端持久数据为准。加载或倒计时阶段跳过的歌曲不冒充已唱，浏览历史不刷新媒体 LRU。

进度通过 SSE 推送，初始连接及重连收到完整快照。处理进程通过标准输出事件汇报阶段，不定时读进度文件。客户端不会轮询状态。

准备进度放在歌曲状态位置：一行步骤名称与百分比，下面一条 3 px 暖金进度条。并行步骤各占一行，播放页复用同一种展示。歌手署名同一行的右侧显示次级文字「已用时 m:ss」，处理步骤与百分比留在下面；窄屏时长文字省略显示，计时不换行，按服务端记录的本次任务开始时间累计，每秒仅更新计时文字；排队时不显示，切换步骤与刷新不归零，结束后移除。没有可靠总量时用不定量进度条，不显示猜测的百分比；无需额外解释文案。渲染完成后的封装、校验仍显示各自状态，直到成品实际可用。

点歌后曲库立即出现该歌曲，语言分类随音频证据更新，不能把排队中的歌曲标为「已准备」。曲库、歌单与播放页共享 SSE 快照；只更新进度时保留按钮节点和键盘焦点，不重建歌曲行。

来源封面与歌曲元数据一起持久化，搜索点歌或下载取得图片地址后立即显示，不能等待音轨与 MV 完成。完成后优先显示本地封面，重试和局部进度更新保留已有图片；沿用现有封面尺寸与裁切，不改变歌曲行布局。歌手页按实际可用的歌曲、视频、发行栏目展示，分别使用「热门歌曲」「歌手视频」「歌手作品」标题。

曲库、搜索结果、预览和链接点歌使用同一套点歌状态。提交中暂时禁用按钮；成功后原位显示「开始唱／查看进度」与「已点 · 第 N 首」，位置以房间实际队列为准，随 SSE 调序、切歌或移除更新。来源 URL 的等价形式按同一视频识别，不靠歌名合并不同录音。失败后恢复点歌；已在待唱里的歌曲避免重复提交，需要再次演唱时仍可从「已唱」主动再点。

共享歌单、准备状态与演唱历史由服务端快照同步。浏览器历史只保存本标签页的搜索、导航和筛选；选曲、播放进度、混音、升降调由 sessionStorage 独立保存，刷新恢复到暂停状态，不缓存共享歌单。网页整体增益固定 100%，不提供总音量或静音控件；清除旧版保存的总音量，由设备音量键控制响度。同一个房间 revision 内也可能发生任务进度、元数据或缓存更新，因此迟到的响应还需按 server_time 拒绝，不能把新进度恢复成旧状态。网页普通点歌在服务端按来源检查是否已入队，主动再点则明确允许重复。共享搜索缓存只复用相同关键词／类型／分页的元数据；各标签页的当前查询与取消请求独立。

播放器使用一个 AudioContext 同时调度背景音乐、伴唱、主唱的三个分段解码音轨；MV 静音播放并跟随同一时钟。人声切换只调节增益，不重新载入视频。首次播放需要用户点击以启用浏览器声音。手机和电脑都在用户点击的当前设备播放，旧的遥控链接也一样；不接管其他设备，不共享播放时钟。

音轨调度使用 AudioContext 的渲染时钟，画面、进度、缓冲和结束判断使用 `getOutputTimestamp()` 映射出的设备输出时钟；接口尚未就绪或不支持时才扣除浏览器报告的输出延迟。变调处理延迟单独保留，避免字幕在设备尚未出声时先跳动，不改写歌词时间戳。

开头的三点准备提示透明叠在已加载的第一帧上，保留封面、歌曲信息与白色预读歌词，不用黑底遮住画面。仍保留完整四秒提示，音轨与视频在歌曲零点一起开始。

播放文件地址带各自的内容哈希。同一首歌修复字幕或音轨后，页面按实际文件版本重新加载并保留本机播放位置与混音；只更新歌名、封面或其他状态不会重载正在播放的音视频。过期版本的分段请求不能读取新版本的字节，预览与正式播放共用同一版本地址。

开播前先等待目标位置的画面解码完成，并确认浏览器原生视频播放能启动，再安排三轨音频；原生视频在倒计时和音频处理延迟期间暂停，仍在设备输出时钟到达起点时继续。视频小幅漂移时只微调静音视频的播放速度；`readyState` 短暂下降但画面仍推进时保持声音连续。明显失步或实际停止推进时冻结共同播放时钟，针对固定位置完成加载后恢复，不能不断跳转追赶仍在前进的声音。视频启动拒绝或超时会停止播放并显示重试入口；旧播放请求的回调不能影响新歌。尚未启用声音的页面不跟随其他设备的时钟反复跳转预览。三条音轨的时钟和速度始终不变。

加载歌曲时预载视频画面，并行解码当前 8 秒片段的三条音轨；当前段全部可用后才允许启动播放时钟。随后按顺序预取约 24 秒，最多保留当前段和后三段，同时仅请求一段的三条音轨；开播不等待全部预取完成。升降调处理器在用户点击并启用声音后初始化，不阻塞首次加载，也不让「开始唱」按钮陷入等待点击的循环。原调和暂停时跳过变调 DSP。后续分段未到齐时先播完已有音频，再冻结共同播放时钟，齐备后恢复。

普通视图将歌曲、播放控制、主唱与升降调分组。伴奏和伴唱始终开启，不提供多余的模式与三轨滑杆；每次 5 个百分点的主唱加减按钮只调节原唱主旋律，不能重载音频或改变播放进度。恢复旧设置时将伴奏和伴唱设为 100%，主唱保留已有百分比，避免隐藏控件后留下关掉的伴奏。两个升降调按钮每次改变一个半音，中间只显示当前调号，不再是第三个按钮。

手机将歌曲与播放按钮放在首行，完整进度条独占第二行，主唱与调号放在第三行。常用按钮保留至少 44 px 的触控区域；通过删掉不需要的控制来降低高度，不靠缩小文字和触控区。实际底栏高度参与页面留白，避免遮住列表末尾。

全屏将同一个底部控制面板移入播放器容器，退出时移回原位，保留事件监听器与状态。底部提供播放／暂停、重唱、下一首、主唱音量、升降调和唯一的播放进度条；隐藏歌曲元数据。主唱明确标注名称与百分比，加减按钮到 0%／100% 时禁用对应方向；全屏只显示播放进度滑杆，避免 iPad 上误触混淆。控件占据视频下方的独立空间，不压住歌词。

导航只改变页面，不重启歌曲。左上角余音始终回主页面、清空搜索并聚焦输入；浏览器后退仍可回到先前的搜索。当前曲目的封面／歌名和底部歌曲区域直接展示播放页；其他歌曲继续预览。显式导航滚到页面顶部，历史恢复与窗口大小变化保留各自的滚动位置。

首页默认优先显示「可直接唱」，仅包括音轨和视频均可播放的成品；其余歌曲仍可在「全部」与语言分类中查找，不再单列补视频分类。刷新或后退遇到已移除的筛选项时回到「可直接唱」。最近唱过放在曲库下方，其他曲目的歌名与封面进入预览，当前曲目直接回播放页；明确的再点按钮入队。

页面文案只保留名称、操作和有用的状态。不要添加装饰英文、口号、缓存／预处理流程说明或重复的操作指引；空状态用短句，空间不足时才显示处理建议，歌词复核状态只用简短标签。

没有可显示字幕时标为「歌词暂缺」，已有歌词但对齐仍待复核时标为「歌词待校对」，不能把缺词说成只是校对问题。新下载和为已有音频补画面时最多选择 720p，音频仍独立选择最佳可用音轨；已有缓存继续复用。

缓存用量放在歌单底部的折叠区，平时只展示已用／上限，展开后才显示容量设置和空间不足的处理提示。统计范围写入使用文档。缓存变化复用房间 SSE，音量只在本机更新，不增加浏览器轮询。

选歌围绕两条路径：知道歌名时查单曲，只知道想唱谁时找歌手，再浏览热门歌曲。默认「综合」把原始关键词交给 YouTube Music，不加歌曲类型或标题匹配限制，保留原站返回的歌曲、专辑、歌手等结果；专辑可进入曲目列表逐首点歌。使用 YouTube Music 中文元数据，中文歌手显示平台提供的中文名，不自行翻译或拼音化；「歌手」搜索直接展开平台首个结果的曲目，沿用紧凑的头像、姓名和歌曲列表，不先展示必须点击的大卡片。有其他候选或下一页时，姓名下方提供低强调的「其他歌手」入口，候选列表保留头像、姓名及原生分页；没有其他候选时不显示入口。单曲歌手署名也可进入热门列表。沿用暗橄榄色与系统字体，琥珀色用于播放、进度和少量选中标记。歌曲、歌手热门和视频结果使用带表头的列表，歌名与封面、歌手（视频为频道）、专辑、播放量、时长分别成列；「点歌」与「找 MV」各占独立操作列，使用一致的高度和内边距，点歌以底色强调、找 MV 使用次级描边，两个按钮的宽度随内容收紧，不撑满操作列；两个按钮均保留左右各 12 px 的框内留白；点歌成功后原位显示「开始唱／查看进度」与「已点 · 第 N 首」；已入队按钮转为播放或查看进度，不重复提交，视频列表的后一列仍为来源链接。歌名下方仅保留版本、专辑类型等识别信息及必要的准备进度、失败提示；曲库、搜索、最近唱过和待唱列表不显示「可直接唱」「待补视频」等静态就绪标签。缺失信息显示短横线；本地曲库与本地搜索复用同一种歌曲行，不展示尚无数据的播放量和专辑列，仍保留独立的「点歌」「找 MV」。依据列表实际宽度收起专辑列，窄屏将歌手与播放数据分行对齐，两个操作仍在右侧并列，不横向挤压或溢出。已加载数量与标题同行，搜索类型与排序紧邻列表。

默认排序先歌曲、再专辑、再其他类型，各类保留平台相关度或歌手热门顺序，歌曲中标题明确标注 Live／现场版的结果靠后；专辑内保留曲目顺序；用户可选择已加载结果按真实播放量、已准备优先或歌名排序。没有播放量就禁用该选项，不能补零、编造热度或将 YouTube 热门顺序标为 KTV 点唱榜。保留平台返回的全部结果和不同版本。歌手首次展开遵循平台顺序，不凭搜索词或译名猜身份；其他结果可随时切换。自动展开不增加浏览器历史层级，返回不落回中转页；显式打开候选列表时保留该列表，刷新不强制再次展开。

「YouTube 视频」保留每一页的完整结果；默认仅将明确标注的现场版后置，不按关键词、认证、类型额外过滤，不限制为 3 条，不请求B站；单曲的「找 MV」进入该搜索。封面点开预览；预览提供原站链接。输入停顿或回车触发，中文组词期间暂停请求，输入或搜索类型变化立即使旧结果失效。预览关闭即移除播放器，弹窗和排序控件内不响应播放快捷键。搜索标题仅作准备阶段的临时名称。

「下一首」在普通页面和全屏的同一个底部控制栏提供；手机底栏使用图标并保留可访问名称。不添加确认弹窗；请求期间禁用按钮，携带点击时的歌曲 ID 防止过期事件重复切歌。

「本地曲库」独立查看已有曲库；已准备状态只关联相同来源 URL，不能把其他版本标成已准备。预览复用本地缓存 MV，点歌复用任务。搜索期间收起首页曲库与历史推荐。

专辑结果使用明确的「专辑」标签和「查看专辑」，进入后再逐首点歌；不能将专辑自动当成其中一首歌。「返回上一级」与浏览器前进／后退恢复原来的列表、排序和滚动位置。关键词、语言分类、当前页面、已加载结果和分页位置随浏览器历史保存，刷新后恢复；共享歌单继续以服务端 SSE 为准，本机进度独立恢复。

歌曲、歌手、歌手热门列表和视频搜索均随下拉按需加载下一页，不设置总结果截断。顶部只显示已加载数量，末尾保留 44 px 高的手动加载／重试按钮与简短状态。追加结果保留现有歌曲行、图片和键盘焦点；换词或切换类型时作废旧请求。到达平台最后一页显示「已经到底了」。分页失败保留已加载歌曲，不自动重试风暴；过期时提供重新搜索。播放量、已准备优先、歌名只排序已加载结果，默认先歌曲再专辑，各类保留平台顺序，并将歌曲中明确标注的现场版后置。

首页在有演唱历史时展示最多四首「最近唱过」与六位「常唱歌手」。最近歌曲按最后演唱时间倒序，按来源去重；不同录音不会因同名而合并。「常唱歌手」按实际演唱次数排序，同次数按最近演唱时间排序，点击沿用歌手搜索。不猜测平台歌手身份，不请求额外元数据或虚构热度。最近歌曲可直接再点，「全部已唱」进入完整历史；没有历史时隐藏此区。

## 美学验收

每次 UI 修改都需按 `AGENTS.md` 完成美学检查，保留整页和局部的实际截图，并写明判断依据；自动化功能测试不能代替这个步骤。当前底栏参考 [Refactoring UI 的公开留白章节](https://refactoring-ui.nyc3.cdn.digitaloceanspaces.com/Refactoring%20UI%20-%20Start%20with%20too%20much%20white%20space.pdf)及 [The Non-Designer’s Design Book 的公开样章](https://www.peachpit.com/content/images/9780133966152/samplepages/9780133966152.pdf)，落实相关元素分组、重复样式的一致性、明确视觉焦点和克制的边框使用。

## 信息层级与元数据

综合／歌手属于搜索内容，YouTube 视频／本地曲库作为另外的来源入口分组；不丢弃上游返回的结果。空专辑列不给固定宽度，歌名优先；移动端将播放量和时长放在同一行，点歌与找 MV 仍独立。已有元数据按视频 ID 合并，缺失字段不能抹去歌手页提供的播放量。播放页去掉装饰唱片与重复歌手署名，普通视图只保留一处下一首，完整画面不裁切。
