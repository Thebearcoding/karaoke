# 歌词检索专项审计

`python -m karaoke.tools.lyric_audit MANIFEST OUTPUT` 对冻结清单调用正式
`prepare_online_lyrics`，只查询歌词，不下载音视频、不运行分离或对齐，也不写入房间队列。
应在与正式服务相同的依赖和已获准网络环境下运行。

清单必须在查询歌词前固定。每项保留 `case_id`、`url`、原始 `metadata`、`duration`、
可选原始 `request`、采样分组 `stratum` 和来源 `origin`。不要用审计者整理的正确歌名、
歌手替换实际输入；已有失败样本和新歌分开汇总。`selection_sha256` 是对 `cases`
按 `json.dumps(cases, ensure_ascii=False, sort_keys=True)` 序列化后的 SHA-256。

```sh
python -m karaoke.tools.lyric_audit manifest.json results \
  --workers 4 --interval 0.4 --protected-root /path/to/service-data
```

`--interval` 限制每个来源新请求的间隔；任务之间共享来源退避，并尊重正式服务的退避。
`--limit` 可先试跑清单的前几项。同一输出目录有进程锁，完成项按输入与检索实现指纹复用；
输入或实现变更必须使用新的输出目录。输出保存完整候选、来源、选择原因、例外和时间，
`report.json` 是不含完整歌词的汇总，`exit.json` 表示本次调用正常结束。
试跑结束不代表整个清单结束，须同时检查汇总的 `pending`。

## 如何解释结果

| 分类 | 含义 |
| --- | --- |
| `no_lyrics` | 正式流程没有返回正文，进一步区分无来源、身份不匹配、正文被拒或请求失败 |
| `exception` | 调用发生未处理异常，保留堆栈 |
| `single_source` | 只有一个独立出版方可供比较 |
| `conflicting_text` | 多来源正文存在较大差异，需要复核 |
| `similar_text` | 至少两个出版方与选中正文的字符编辑相似度达到 90%，仍有差异 |
| `corroborated_text` | 至少两个出版方的标准化正文一致 |

标准化只忽略大小写、繁简、标点和空白；保留词序、重复段、正文增删。
同一出版方由不同站点转发只计一次。汉字／假名、译文、不同录音剪辑仍可能产生差异。
报告同时保留其他来源的冲突，不能因存在两个一致来源就掩盖第三个来源的不同正文。

**以上是检索和来源一致性指标，不是歌词准确率。** 不同出版方也可能转载同一份错误文本。
外部参考可以放在项的 `reference`（`lines`、`publisher`、`url`）中，仅供输出后比较，
不会传给检索函数；若出版方已参与检索，报告标为 `not_independent`。
参考出版方的独立性、曲目身份与录音版本仍需人工核实。

人工复核应覆盖全部严重差异，以及预先选定的各语言／输入类型通过样本。
分别记录错歌、错译文、缺句、重复段、非歌词署名、表记差异和无法判定；不能将它们都计为错歌。
没有听完整录音或独立正文参考的样本，不宣称逐句完整或逐字起音正确。

## 修复回归

同一轮修复沿用原始清单与输入哈希，输出到新的迭代目录，保留基线和每一轮代码指纹。
可以复用内容哈希相同的 HTTP 响应；必须重新执行修改过的解析、身份匹配和正文选择。
简介中的歌词可来自明确的歌词区段，或与已有正文大范围重合的连续区段；不能把宣传文案
或模型补写的内容作为歌词。MV 缺少歌词页时可读取同一作品的专辑版本，记录实际来源和
版本差异，仍由后续对齐验证它是否适合当前录音。

正文长度不能证明完整：夹入译文、发音说明甚至其他作品的候选可能反而最长。不能仅因一份
正文被另一份包含就将其判为片段并丢弃；保留完整候选，由后续录音验证。MV 的片头、片尾会改变总时长，单独的
时长差异不应否决正文互证；已知不同现场演出仍保留版本优先级与回退诊断。

失败统计必须保留原始检索分类，并附上可复核的判定：

- **hard fail**：演唱歌曲没有可用正文，或确认选中了错歌、混入译文／署名、实质漏段等错误。
- **soft fail**：某来源异常但有可用回退，或只有表记、录音版本等差异；保留原因和实际采用来源。
- **不适用**：有明确证据的纯音乐样本，仍列在原清单中，不能算成歌词检索通过。
- **待复核**：仅有来源冲突或自动模型怀疑，证据不足；不能当作已确认错误，也不能报成准确率通过。

自动内容复核只提出疑点。它必须指向实际选中正文中的位置，不能把未选中来源的问题记到
成品上；即兴哼唱、多语种演唱、正常重复都不能仅凭模型猜测删除。完成通知中的“无 hard fail”
须说明验收范围，且不能隐去仍未判定的样本。

## 根因与规则边界

修复先区分格式解析、身份依据和质量判断。格式问题在来源入口统一解析，身份回退复用共有
匹配函数；不要把某首歌的表现改写成全局长度阈值、语言黑名单或新的删词规则。

| 根因 | 共有修复 | 必须保留的反例 |
| --- | --- | --- |
| 把 LRC 的时间标签留在文本里，导致署名识别失效 | 先解析时间标签及其标志，再判断正文／署名；时间不用于对齐 | 真正歌词及重复顺序不变，只有署名的响应不能成功 |
| 把全部参与人员相同当作作品相同的前提 | 完整署名优先；同名作品有明确共同署名时才可作带差异记录的回退 | 无共同署名的同名歌曲不能混入，严格录音接口行为不变 |
| 把篇幅更长、多家转载一致当作正确性证明 | 保留候选和原始正文；用来源和实际录音复核内容边界 | 真实双语、和声、说唱署名、重复演唱不能仅凭模型怀疑删除 |

新增来源先验证它实际返回的曲目身份和正文；HTTP 200 或搜索结果摘要不表示运行环境已取得
目标歌词。确认不可访问时保留访问错误，不用别的歌曲或猜测文本补齐统计。
LyricsWeb 只读取匹配录音的 `MusicRecording.recordingOf.lyrics.text` 和出版方信息，
不提取页面的 AI 释义。搜索响应与详情页身份都要匹配；来源自己的不透明 ID 只用于定位，
不要求它满足另一家站点的数字 ID 格式。所有来源继续复用相同的作品匹配与正文解析。

同一个视频 ID 的歌词页也可能挂错语言版本。已有候选涉及多种语言时，处理阶段复用现有
音频语言检测，只调整这些完整候选的尝试顺序；检测失败、语言不明确或没有对应候选时保留
原顺序。所有候选和既有对齐校验仍保留，不按语种删词，也不把语言检测当作正文正确性的证明。
