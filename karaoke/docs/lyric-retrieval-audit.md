# 歌词检索专项审计

`python -m karaoke.tools.lyric_audit MANIFEST OUTPUT` 对冻结清单调用正式
`prepare_online_lyrics`，只查询歌词，不下载音视频、不运行分离或对齐，也不写入房间队列。
应在与正式服务相同的依赖和已获准网络环境下运行。

清单必须在查询歌词前固定。每项保留 `case_id`、`url`、原始 `metadata`、`duration`、
可选原始 `request`、采样分组 `stratum` 和来源 `origin`。不要用审计者整理的正确歌名、
歌手替换实际输入；已有失败样本和新歌分开汇总。`selection_sha256` 是对 `cases`
按 `json.dumps(cases, ensure_ascii=False, sort_keys=True)` 序列化后的 SHA-256。

```sh
python -m karaoke.tools.lyric_audit manifest.json results \
  --workers 4 --interval 0.4 --protected-root /path/to/service-data
```

`--interval` 限制每个来源新请求的间隔；任务之间共享来源退避，并尊重正式服务的退避。
`--limit` 可先试跑清单的前几项。同一输出目录有进程锁，完成项按输入与检索实现指纹复用；
输入或实现变更必须使用新的输出目录。输出保存完整候选、来源、选择原因、例外和时间，
`report.json` 是不含完整歌词的汇总，`exit.json` 表示本次调用正常结束。
试跑结束不代表整个清单结束，须同时检查汇总的 `pending`。

## 如何解释结果

| 分类 | 含义 |
| --- | --- |
| `no_lyrics` | 正式流程没有返回正文，进一步区分无来源、身份不匹配、正文被拒或请求失败 |
| `exception` | 调用发生未处理异常，保留堆栈 |
| `single_source` | 只有一个独立出版方可供比较 |
| `conflicting_text` | 多来源正文存在较大差异，需要复核 |
| `similar_text` | 至少两个出版方与选中正文的字符编辑相似度达到 90%，仍有差异 |
| `corroborated_text` | 至少两个出版方的标准化正文一致 |

标准化只忽略大小写、繁简、标点和空白；保留词序、重复段、正文增删。
同一出版方由不同站点转发只计一次。汉字／假名、译文、不同录音剪辑仍可能产生差异。
报告同时保留其他来源的冲突，不能因存在两个一致来源就掩盖第三个来源的不同正文。

**以上是检索和来源一致性指标，不是歌词准确率。** 不同出版方也可能转载同一份错误文本。
外部参考可以放在项的 `reference`（`lines`、`publisher`、`url`）中，仅供输出后比较，
不会传给检索函数；若出版方已参与检索，报告标为 `not_independent`。
参考出版方的独立性、曲目身份与录音版本仍需人工核实。

人工复核应覆盖全部严重差异，以及预先选定的各语言／输入类型通过样本。
分别记录错歌、错译文、缺句、重复段、非歌词署名、表记差异和无法判定；不能将它们都计为错歌。
没有听完整录音或独立正文参考的样本，不宣称逐句完整或逐字起音正确。

## 修复回归

同一轮修复沿用原始清单与输入哈希，输出到新的迭代目录，保留基线和每一轮代码指纹。
可以复用内容哈希相同的 HTTP 响应；必须重新执行修改过的解析、身份匹配和正文选择。
简介中的歌词可来自明确的歌词区段，或与已有正文大范围重合的连续区段；不能把宣传文案
或模型补写的内容作为歌词。MV 缺少歌词页时可读取同一作品的专辑版本，记录实际来源和
版本差异，仍由后续对齐验证它是否适合当前录音。

正文长度不能证明完整：夹入译文、发音说明甚至其他作品的候选可能反而最长。不能仅因一份
正文被另一份包含就将其判为片段并丢弃；保留完整候选，由后续录音验证。MV 的片头、片尾会改变总时长，单独的
时长差异不应否决正文互证；已知不同现场演出仍保留版本优先级与回退诊断。

失败统计必须保留原始检索分类，并附上可复核的判定：

- **hard fail**：演唱歌曲没有可用正文，或确认选中了错歌、混入译文／署名、实质漏段等错误。
- **soft fail**：某来源异常但有可用回退，或只有表记、录音版本等差异；保留原因和实际采用来源。
- **不适用**：有明确证据的纯音乐样本，仍列在原清单中，不能算成歌词检索通过。
- **待复核**：仅有来源冲突或自动模型怀疑，证据不足；不能当作已确认错误，也不能报成准确率通过。

自动内容复核只提出疑点。它必须指向实际选中正文中的位置，不能把未选中来源的问题记到
成品上；即兴哼唱、多语种演唱、正常重复都不能仅凭模型猜测删除。完成通知中的“无 hard fail”
须说明验收范围，且不能隐去仍未判定的样本。

录音复核中的失败也要追到证据使用方式：识别未覆盖一段已知歌词时，先在原音频和分离人声
上用现有声学模型定位，再按双方支持的范围重新对齐，不能让重复的注意力对齐先耗尽预算。
相同音频范围和正文的声学请求复用结果（包括不可用结果），范围改变才重新计算。
这些范围只用于安排后续计算，最终完整性与时间约束照常验证。重试摘要没有定位锚点，
不能用于替换时间约束；缺少新证据时继续保留原约束。
已通过位置校验的局部修复，即使没有增加歌词行数也应保留；全局续修必须保住此前每一条
可用歌词，不能仅比较数量，更不能因数量不变而退回旧的错位时间。

## 根因与规则边界

修复先区分格式解析、身份依据和质量判断。格式问题在来源入口统一解析，身份回退复用共有
匹配函数；不要把某首歌的表现改写成全局长度阈值、语言黑名单或新的删词规则。

| 根因 | 共有修复 | 必须保留的反例 |
| --- | --- | --- |
| 把 LRC 的时间标签留在文本里，导致署名识别失效 | 先解析时间标签及其标志，再判断正文／署名；时间不用于对齐 | 真正歌词及重复顺序不变，只有署名的响应不能成功 |
| 把全部参与人员相同当作作品相同的前提 | 完整署名优先；同名作品有明确共同署名时才可作带差异记录的回退 | 无共同署名的同名歌曲不能混入，严格录音接口行为不变 |
| 把篇幅更长、多家转载一致当作正确性证明 | 保留候选和原始正文；用来源和实际录音复核内容边界 | 真实双语、和声、说唱署名、重复演唱不能仅凭模型怀疑删除 |
| 对混合繁简输入重复做单向转换，使简体词变成另一种写法 | 身份、正文比较和审计指标共用先转繁再转简的归一化 | 重复归一化不改变身份；保留原始正文，不合并「幺／么」「乾坤／干坤」等不同字词 |
| 把目录的别名和译名字段当成互斥回退，丢失已有译名 | 合并来源明确给出的两个字段，继续使用相同的身份匹配 | 存在别名时仍能匹配译名；没有身份依据的同名作品不能混入 |
| 多家来源把注音串入正文，靠票数压过正确正文 | 仅当全部差异都精确对应结构化注音的位置与读音时，优先不含注音的完整正文 | 括号里的实际回应唱词、正文改写或无法解释的差异不受此规则影响；原候选保留 |
| 段落标签带演唱／演奏署名时未被识别 | 同一段落标签语法支持可选序号与署名；只移除完整标签行 | 中间的演奏说明不截断后续歌词；实际伴唱、感叹词和正文中的 solo 保留 |
| 复制的页头将歌名与 by 歌手署名分成两行，并混入播放控件文字 | 只在开头的两行分别匹配已知歌名及歌手时移除页头 | 正文中的同样两行、单独歌名或人名、不同署名以及普通 by 开头唱词均保留 |
| 将明确的 Version／Ver. 版本标记当作作品标题，漏掉其他发行版的歌词 | 作品名作为查询别名，版本标记仍参与录音匹配与优先级 | 相同版本优先；不同作品、普通括号副标题与纯伴奏不能因此混入 |
| 曲名中的「國／粵」及「国语版」等语言版本写法不一致，丢失同一作品的歌词 | 版本解析支持中文「版」后缀与目录中的国／粤简称；语言名称经现有语言注册表归一化，作品名仍用于共有检索 | 国语／粤语或日语／英语不能当成同一录音版本；无明确版本语法的括号副标题保留 |
| 查询与匹配各自解析标题说明，查询发出的名字反而不是匹配认可的作品名 | 两条路径复用同一标题解析，统一处理明确的发行版和影视出处说明 | 原始标题保留用于版本排序；普通副标题和未标明性质的括号文字保留 |
| 制作名单中的复合职责或发行说明漏认，误把下一项署名当成正文终点 | 署名字段复用乐器／制作职责语法，支持斜杠组合；已识别页头中的作品说明单独解析 | 普通冒号唱词和正文后的作品说明保留，不按行数或音量猜正文起点 |
| 双语职责之间没有空格，或职责带首席／执行等限定词，导致署名进入唱词 | 同一职责语法支持限定词及中拉文字边界，仍要求冒号前全部是已知职责 | 仅含 music、chief 或中文乐器字样的实际歌词保留，不放松后续时间校验 |
| 合唱歌词用空的「演唱者：」行切换声部，混入正文 | 仅解析已署名演唱者的全名或无歧义简称，以及多人演唱中的合唱标记 | 实际唱出的姓名、带正文的冒号行、未知或有歧义的简称都保留 |
| 方括号页头中的日文引号未解析，导致作品标题混入候选正文 | 标题解析同时支持英文引号、书名号及「」『』，仍要求完整页头与已知作品名称匹配 | 不同作品的标题、无方括号的实际唱词和未知方括号内容保留 |
| 页头的多人署名只与单个歌手比较，导致页头被当成正文 | 页头解析与来源身份核对共用多人署名匹配 | 只有完整署名匹配才移除，缺一人或换一人的正文保留 |
| 用界面译名解析来源原文页头；正文无效时丢掉同一视频的有效身份 | 正文使用所属录音的来源名称解析；身份恢复同时读取有效、无效正文携带的同源元数据 | 另一视频的身份不得复用；专辑回退仍绑定实际歌词所属视频，已读取的结果复用 |
| 录音署名只有拉丁译名，歌词源只登记原名 | 常规检索失败后，按该录音已有的歌手 ID 读取平台名称；响应缓存复用 | 不按名字搜索猜歌手，不替换用户明确指定的署名；已有可用正文时不增加请求 |
| 单个来源的罗马音被当作别的语言，已存在的双语艺名没有进入检索 | 仅在同一视频确认的歌手 ID 等于频道 ID、且名字包含原署名时，复用频道的双语别名补查单源结果 | 普通上传者不能覆盖歌手；保留显式署名；新正文仍需独立来源支持，不能只改语言标签冒充原文 |
| 已有来源彼此冲突，却没有使用同一录音已经给出的原名补查 | 尚未获来源互证时，复用该视频确认的未查询曲名／艺名；补查结果获互证才替换已有正文 | 已互证结果不增加请求；另一视频、用户显式署名及无互证的新候选均不能覆盖原结果 |
| UtaTen 展示标题把歌手和影视出处拼在一起，误判为不同歌手 | 使用明确绑定当前歌词页的 MusicComposition / recordedAs.byArtist 及其声明的别名 | 其他页面的结构化数据、损坏的数据和同名不同歌手不能覆盖当前身份；原文和注音位置不变 |
| 纯文本来源把带引号的显示词组和括号注音连续写出，导致同一词对齐两遍 | 只在另一已发表 ruby 精确确认相同文字和读音后，将括号注音移入注音数据；原显示词组及来源证据保留 | 未确认的括号唱词、不同读音或配对错误的引号不改动；局部读音参考不能冒充整首歌词，渲染复用同一注音 |
| 紧贴汉字的括号注音被算入正文差异，使结尾不同的候选反而获得更高相似度 | 同样用已发表 ruby 确认完整汉字片段及读音，比较正文前分离注音；原文、注音和不同结尾的候选全部保留 | 不截取汉字片段的后缀去猜匹配，不删除空格隔开的括号唱词；有注音的来源不因此被视为整首歌词权威 |
| 歌词页明确标注「和訳」，正文却混排原词和译文 | 保留原响应与原因，继续找原词来源；没有标明正文边界时不按语言猜测删除 | 未标译文的真实双语歌词照常保留；同页身份匹配不能把译文变成演唱正文 |
| 将歌名与全部署名拼成查询，导致检索漏召回 | 与 LINE Music 一样，NetEase 精确查询无可用结果后按歌名召回，沿用相同身份核对 | 无共同署名的同名歌曲仍不匹配；精确查询成功时不追加查询 |

新增来源先验证它实际返回的曲目身份和正文；HTTP 200 或搜索结果摘要不表示运行环境已取得
目标歌词。确认不可访问时保留访问错误，不用别的歌曲或猜测文本补齐统计。
LyricsWeb 只读取匹配录音的 `MusicRecording.recordingOf.lyrics.text` 和出版方信息，
不提取页面的 AI 释义。搜索响应与详情页身份都要匹配；来源自己的不透明 ID 只用于定位，
不要求它满足另一家站点的数字 ID 格式。所有来源继续复用相同的作品匹配与正文解析。
搜索接口可能在每首歌重复内嵌整份歌手资料，按它自己的有界响应读取后只缓存 ID、名称、
歌手及详情路径，并保留原响应哈希和大小；歌手对象与列表统一解析。歌词详情仍使用原来的
正文读取限制，搜索响应的大小不参与歌词质量判断。
该接口的歌曲查询使用歌名：它把歌名和歌手名分别检索，拼接二者会退化为歌手曲库，
漏掉不在曲库首屏的目标歌。结果仍按原来的歌名、署名和版本核对，不放宽身份匹配。
该接口仅接受 2–120 字符；不符合长度的歌名保持原样，查询已知别名或歌手曲库，
结果仍须匹配原歌曲，不能截断标题或直接接受曲库首项。
来源错误保留原始 HTTP 状态与重试时间。离线批量审计按来源串行请求，并等待实际退避
截止时间后进行最多两次重试；其他来源独立继续，认证错误不重试。持续不可用仍计入
来源缺失证据，不能把批量限流当成已经确认没有歌词。

同一个视频 ID 的歌词页也可能挂错语言版本。已有候选涉及多种语言时，处理阶段复用现有
音频语言检测，只调整这些完整候选的尝试顺序；检测失败、语言不明确或没有对应候选时保留
原顺序。所有候选和既有对齐校验仍保留，不按语种删词，也不把语言检测当作正文正确性的证明。
