# 自动检查分离与字幕

## 检查器也需要验证

音轨可解码、三轨逐比特还原、字幕覆盖完整，是必要的工程检查。它们不能证明声部分配正确或字词踩点准确。新的离线评分入口把以下证据分开保存，不自动修改歌曲状态：

```sh
.venv/bin/python -m karaoke.tools.quality --manifest INPUT.json --output REPORT.json
```

报告保存输入文件 SHA-256。输出路径必须是新文件，以免覆盖旧证据。它只读现成文件，不下载、跑模型或重建歌曲。

## 字词起音

输入事件为 `[{"id": 0, "text": "word", "start": 1.23}]`。参考事件来自同一录音的独立人工标注；候选缺失的时间写 `null`，保留原 ID 和词。重复歌词也各有 ID。不允许评分时拟合 offset、删除错词或合并参考单位。

```json
{
  "onsets": [{
    "id": "recording-1",
    "reference": "reference.json",
    "reference_provenance": "同一录音的独立人工起音标注及其来源",
    "prediction": "predicted.json",
    "verifier": "independent-model.json"
  }]
}
```

- 有 `reference`：报告 Hit@50/100/250 ms、误差分位数、提前／滞后、缺失。阈值沿用[起音验收](word-onset-metrics.md)，不因为困难样本降低。
- 有 `verifier`：缺失证据、合并高亮、两个结果相差超过 100 ms 时标记复核。标记保留原文字和两个时间，不能因弱唱未被识别而删除歌词。
- 两者都有：另外测疑点检查器的精确率、召回率、误报率和未标记词中的错误率。**两个模型一致仍可能同时出错**。
- 无人工标注：`accuracy: null`。没有发现疑点不等于通过准确率验收。

现有中文事件可以通过 `word_events(cues, 'Chinese')` 提取；合并的两个字仍作为两个事件计数。日语的参考单位须独立固定为对应的发音组，不能用候选的分词反过来定义答案。

## 分离质量

```json
{
  "window_seconds": 1,
  "stems": [{
    "id": "recording-2",
    "reference_provenance": "录音发布者提供的原始多轨及角色标注",
    "references": {"lead": "truth/lead.wav", "backing": "truth/backing.wav", "music": "truth/music.wav"},
    "predictions": {"lead": "result/lead.wav", "backing": "result/backing.wav", "music": "result/music.wav"}
  }]
}
```

参考和输出角色、采样率、声道和帧数必须相同，不自动重采样、挪时间、交换角色或调整音量。具体定义见[分离指标](lead-backing-metrics.md)。

- 固定增益重建分数及目标增益：查目标被削弱或丢失。单看忽略整体音量的 SI-SDR，会把音量减半的正确波形当成完美输出。
- SI-SDR、SI-SIR、SI-SAR：分别报告重建、参考声部干扰、无法由参考解释的误差。参考声部高度相关时不给出不可辨识的 SIR/SAR。
- 逐窗口报告与 P10：保留弱人声窗口，不能用整首平均掩盖一小段丢字。仅数字全零的参考窗口单列输出泄漏电平；不能用候选音量筛选窗口。
- 精确相等／全零造成的无穷分数，仅为 JSON 存储封顶至 ±300 dB；这不是质量门槛。

只有混音和模型输出时，没有真实分离质量分数。原曲、完整人声、主唱、伴唱、伴奏的独立识别差异可以帮助定位，但不能将某个模型的输出当成真值。MUSDB 的合并人声参考也不能证明主唱／伴唱分配正确。

## 已执行的检查器验证

在既有开发数据上复查，无新下载、无分离模型重跑：

- 6 首 Jamendo、1,876 个人工词起点：对既有候选与另一个声学模型的结果，用固定 100 ms 差异筛疑点。在候选的 376 个超过 100 ms／缺失错误中抓到 119 个，漏掉 257 个，另有 146 次误报。这个规则只适合作疑点提示，**没有达到自动放行要求**。这些是旧候选的检查器实验，不是当前整条 pipeline 的新精度成绩。
- 对同批人工事件注入提前 300 ms、延后 300 ms、缺失与合并亮字，24 组错误控制均不能通过原起音门槛；6 组未改变事件通过。
- 在 6 段真实 MUSDB 分轨上注入人声消失、角色交换、人声减半、串音及弱尾音丢失，逐轨／逐窗口指标均反映已知损伤。30 组损伤控制与 6 组原样控制用于验证评分器，不代表当前分离模型的成绩，也没有真实主唱／伴唱标签。

行为回归还覆盖：两个检查器共同错位、检查器单独出错、弱词缺证据、局部低电平目标丢失、角色交换、相关参考不可辨识。实际歌曲的人工反馈只记录其确认的事实；例如“这个字有唱但很弱”不能变成未标注的毫秒起点。

### 中文人工标注对照（2026-10-01）

从 [MIR-1k-partial-align 的独立逐字标注](https://github.com/navi0105/LyricAlignment/tree/main/dataset_preprocessing)中，按文件名字典序固定前三首 `Ani_1.wav`、`abjones_1.wav`、`amy_1.wav`，共 218 个字。使用对应整段录音；模型只收到音频和完整文本，保存预测后才读取人工起点。没有按参考时间裁剪、平移或拟合时间轴。

| 直接对齐器 | Hit@50 ms | Hit@100 ms |
| --- | --- | --- |
| SOFA，干声 | 103/218（47.2%） | 183/218（83.9%） |
| MMS_FA，干声 | 155/218（71.1%） | 205/218（94.0%） |
| MMS_FA，混音 | 161/218（73.9%） | 207/218（95.0%） |

这是三个固定样本的直接对齐对照，**不是正式 pipeline 或百首测试的精度**。SOFA 在三个样本上的有符号误差中位数分别约为 −45、−39、−63 ms；不据此给新歌加统一偏移。用 SOFA/MMS 相差 100 ms 筛查时，35 个实际错误中抓到 24 个、漏掉 11 个，另有 35 次误报，仍不足以自动证明字幕正确。

另外检查了[中文歌声音素 CTC 候选](https://huggingface.co/lyonlu13/wav2vec2-large-zh-singing-phoneme-ctc)（`aa19db9ca380d6aac0f8b5dd5e7c6fa6359f0518`）。固定 20 秒音频块并保留两侧上下文，不使用参考时间切块。其原始“词分隔符”共给出 192 个事件，在 ±100 ms 内只能与 143/218 个人工起点一一匹配；取分隔符后的首个音素事件则匹配 178/218 个。这是无词身份的事件检测召回数，不能称为逐字 Hit@100 ms。分隔符在个别失败片段上恰好接近另一模型，不能据此把它改作起点并接入生产。这次候选未被采用。
