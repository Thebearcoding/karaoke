# 整曲回归运行

整曲测试通过正常点歌接口注册任务，使用服务的 10 GiB 共享缓存。验证完成后只移出本控制器添加且非当前播放的条目；保留用户歌单和播放状态。定向音频测试使用 `run_probe` 的单实例锁和缓存监控，不能裸跑处理子进程。应用的点歌队列容量与测试并发是不同设置。

## 普通点歌策略：音轨与字幕各跑一遍

```sh
python -m karaoke.tools.playback_sweep --manifest MANIFEST --data-dir DATA --report REPORT --prepared-dir INPUTS
```

使用已冻结的清单和预备歌词包。暂停普通 worker，逐首处理已有同源音频；歌词包携带源文件哈希、完整备用歌词及来源证据。纯计算可以放在另一台主机，不能丢掉本机检索的备用来源。每首只提交一次，软件失败保留诊断并继续下一首；缓存、服务、版本或来源身份冲突停止批次。`REPORT` 同名的 `.pause` 文件使控制器在当前首结束后停下。暂停退出不等于整批完成。

修复原例时可重复传入 `--case-url URL`，仍读取原固定清单，但只运行指定样本并写入新的独立报告。报告分别记录固定清单大小和本次实际样本数；不能用两首定向通过冒充完整 100 首，也不能在同一报告中更换选取范围。

独立报告的 `audio_attempts` 区分：

- `clean`：完整产物通过，未使用已记录的恢复措施。
- `soft_fail`：某步骤失败后，备用来源或局部回退已产出完整可用结果，且最终校验通过。不能仅把异常改成警告就计为恢复。
- `hard_fail`：仍没有完整可用结果。例如缺歌词行、未解决的声学时间矛盾、损坏音轨、缺产物或完整解码失败。基础设施错误单独注明，不能当成歌曲算法失败。

七项音轨／字幕产物必须实际存在，文件哈希、float64 三轨格式与有限数值、全长 MP3 解码、字幕和输入正文完整性、有效有序的时间轴均须通过。回退提示不是独立人工起音准确率，也不证明分离纯度。这里不生成或验证 MV，不改写历史严格音频和完整 MV 账本。修复后保留旧报告，先验证失败原例，再完成同一实际版本的全部样本；不同版本通过数不能相加。诊断中的恢复事件也可能出现在最终硬失败的歌曲里，统计时同时区分事件次数、涉及歌曲数与最终结果。

起音复核已确认行首明显偏移、但相邻字仍阻止局部替换时，允许用已确认的位置重新取一次该句的声学窗口。仅改变模型观察范围，不直接挪动字幕；复核沿用原来的跨模型证据、相邻词顺序和可听声音约束，保留此前已确认的矛盾。二次取证失败或仍有冲突时保持硬失败，不用重新采样次数或较宽阈值换取通过。

旧对齐把多个字合成一个单元时，局部替换同时复用已完成的跨模型逐字复核，不能只复核旧单元的首字、让内部字重新退回较粗的单模型位置。只有已确认偏移的旧起点触发修改，替换范围之外的字保持原样；声音不足或证据分歧仍保留失败。

声音支持检查沿用证据类型：CTC 起点事件检查起点附近，已交叉确认的完整发音区间检查该区间。局部替换截短区间后仍需按同一规则复核，不能先按完整词音确认、再换成起点事件的规则否决；未经交叉确认的位置不放宽。

发音模型一致标为闭塞音素 `cl` 的内部停顿不要求有声能，例如日语促音。它仍须由原音与人声的定位共同支持，并夹在通过声音检查的相邻单元之间；不能把元音缺声、整段静音或边缘缺失作为闭塞放行。诊断保留相应的音素和区间依据。

歌词来源省略语言时，备用正文继承当前已确定的语言；明确的制作名单在来源解析时剔除，包括名单换行后的制作人员姓名。对齐器产生的错误正文只作为原始诊断保留，相应歌词行标记为未定位，让整份备用歌词仍有机会完成对齐；最终缺行或正文不一致继续阻止发布。

声学定位逐句检查正文覆盖，单句缺少发音映射不能丢弃同一窗口内其他句的有效证据。局部识别漏掉已知歌词时也可使用这条声学回退；长窗口只识别出部分句子仍需定位剩余句子，共用原有计算预算，重复窗口复用识别结果。

发现更小的可靠声学范围后，优先完成该范围内的恢复，再处理其他片段，避免前面已经付出的定位计算因为排在队尾而无法使用。总重试预算和最终质量检查不变。

分离人声可能损伤合唱或较轻的演唱。局部对齐失败时，允许在同一不超过 45 秒的范围内改用原混音对齐同一正文，计入原有预算并保留两份预测；只有正文、范围和顺序全部有效才采用，之后继续最终声学与产物校验。

## 完整 MV 回归与固定样本

```sh
python -m karaoke.tools.soak sample --manifest karaoke/service-data/soak-100/manifest.json --data-dir karaoke/service-data
python -m karaoke.tools.soak run --manifest karaoke/service-data/soak-100/manifest.json --data-dir karaoke/service-data
```

抽样默认种子为 `20261001`，从多个音乐人官方来源元数据池抽取中文 40、日文 30、英文 30 首，时长 90–480 秒。语言分组依据检索音乐人，实际处理仍自动识别，不传歌词或语言提示。它是分层随机样本，不代表全球歌曲均匀随机。池和清单是本地测试数据，不提交 Git。正式运行前固定清单和 SHA-256；不能依据处理结果替换失败歌曲。

完整 MV 任务状态通过房间 SSE 接收。每首完成后独立检查最终文件 SHA-256、HTTP 首尾 Range 内容、三轨 float64 格式与有限数值、字幕覆盖与时间顺序，以及整段 MV 和三条 MP3 解码。全部通过才记为 `passed`；三轨重组误差仅作诊断，不要求逐比特还原或改写音频样本。

所有样本必须在同一最终流水线版本上通过。部署修复后优先重试失败样本，并重新验证旧版本通过的样本；新提交的测试条目按软件失败优先，同类保持抽样顺序，不改清单顺序或房间中已有条目的顺序。结果按实际提交顺序收集，避免等待清单里排在前面、实际尚未处理的歌，延误已有结果的校验和缓存释放。`force` 用于完整重验旧版本成功样本，普通失败重试使用阶段检查点。清单保留历次任务 ID、版本、耗时、错误指纹和验证证据。媒体可以按 LRU 回收，不影响已经保存的验证记录。

完整 MV 控制器遇到软件错误时停止新一轮提交，继续记录已排队任务的结果。失败任务的轻量 JSON 诊断压缩保留在本地测试记录目录。维护者复现、修正通用逻辑、补充必要行为测试、运行回归，待实际处理进程结束且未播放时部署，再执行 `run`；不需要清空用户歌单。创建同目录 `manifest.pause` 会停止控制器的新操作，已提交给应用的任务继续执行。文件锁防止启动重复控制器。

长期恢复与修复由本聊天的维护 heartbeat 推进。无人运行控制器时清单不会自行变成完成。每次报告分别列当前版本通过数、软件错误、外部受阻和未运行数；只有当前版本 `100/100` 才宣布完成。

外部重试按具体错误和服务端提示处理：临时网络错误短退避，尊重 `Retry-After`；429 限制对应来源或模型，单视频 403 不冻结整个站点。登录验证、认证失败、额度不足或请求过大需要访问条件或请求本身改变，不能靠盲等重试解决。登录阻塞和来源限流可以同时存在，各自保留；修代码和等待退避结束都不自动解除登录阻塞。历史人为两／四小时冷却不恢复，外部模型失败不阻塞不依赖模型的纯下载。
