# 整曲回归运行

`python -m karaoke.tools.soak` 对现有本地 API 做整曲测试，使用同一个 worker 和 10 GiB 缓存。测试不增加待唱条目，不控制播放器；当前正在播放或处理用户任务时等待，再提交一首。不要并行启动另一个音频 worker。

```sh
python -m karaoke.tools.soak sample --manifest karaoke/service-data/soak-100/manifest.json --data-dir karaoke/service-data
python -m karaoke.tools.soak run --manifest karaoke/service-data/soak-100/manifest.json --data-dir karaoke/service-data
```

抽样默认种子为 `20261001`，从多个音乐人官方来源元数据池抽取中文 40、日文 30、英文 30 首，时长 90–480 秒。语言分组依据检索音乐人，实际处理仍自动识别，不传歌词或语言提示。它是分层随机样本，不代表全球歌曲均匀随机。池和清单是本地测试数据，不提交 Git。正式运行前固定清单和 SHA-256；不能依据处理结果替换失败歌曲。

任务状态通过房间 SSE 接收。每首完成后独立检查最终文件 SHA-256、HTTP 首尾 Range 内容、三轨 float64 格式及按 `(主唱 + 伴唱) + 伴奏` 重组后的源 PCM 指纹、字幕覆盖与时间顺序，以及整段 MV 和三条 MP3 解码。全部通过才记为 `passed`；模型置信度和时间单调不是人工起音准确率，也不能证明分离纯度。

所有样本必须在同一最终流水线版本上通过。部署修复后优先重试失败样本，并重新验证旧版本通过的样本；`force` 用于完整重验旧版本成功样本，普通失败重试使用阶段检查点。清单保留历次任务 ID、版本、耗时、错误指纹和验证证据。媒体可以按 LRU 回收，不影响已经保存的验证记录。

遇到软件错误，控制器停止提交新歌，维护者保留失败诊断、复现、修正通用逻辑、补充必要行为测试、运行回归、空闲时部署，然后重新执行 `run`。下载认证／限流等外部错误按来源退避，至少两小时，单个样本三次自动失败后需要明确处理；不绕过站点验证，不无限重复下载，也不把外部失败算通过。创建同目录 `manifest.pause` 可让控制器在当前任务完成后停止。文件锁防止启动重复控制器。

长期恢复与修复由本聊天的维护 heartbeat 推进。无人运行控制器时清单不会自行变成完成。每次报告分别列当前版本通过数、软件错误、外部受阻和未运行数；只有当前版本 `100/100` 才宣布完成。
