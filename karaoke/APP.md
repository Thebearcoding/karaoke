# 退学 KTV · 网页卡拉 OK

手机、平板和电脑都提供点歌台、正在播放、待唱列表和常驻底部控制栏；在点击播放的设备上发声。未播放时不下载视频或音轨，暂停会取消未完成的媒体加载；播放时只缓冲附近片段，恢复时复用已加载音频。歌单同步与已点歌曲的服务器准备仍会使用网络。手机横竖屏切换不会停止播放，缓存设置仍只在平板和电脑显示。日间主题使用红色，夜间主题使用琥珀黄。

## 运行

从工作区根目录启动：

```sh
.venv/bin/python -m karaoke.api
```

打开 <http://127.0.0.1:8746/>。网页与 API 由同一个服务提供，不需要 Node 构建或额外前端服务器。依赖沿用 [API.md](API.md)。

## 使用

右上角月亮／太阳按钮切换日间与夜间外观。未手动选择时跟随系统外观，手动选择会保存在当前浏览器，刷新后保留，同源标签页同步；其他设备可独立选择。切换外观不会影响播放。

### 多人使用时的状态

| 范围 | 包含的状态 | 刷新后 |
|---|---|---|
| 房间共享 | 待唱顺序、已唱记录、准备状态、缓存上限 | 从服务端重新同步，所有人一致 |
| 当前浏览器 | 本机选曲、播放意图与位置、主唱音量、升降调 | 同一浏览器的标签页共享，只有一个标签页发声；重新打开后仍需浏览器允许声音 |
| 当前浏览器标签页 | 搜索词、搜索类型、结果与分页、排序、语言筛选、正在浏览的页面、待唱／已唱 tab、历史筛选、主页面滚动位置 | 恢复各自的状态；前进／后退不改变音量 |
| 临时交互 | 预览弹窗、展开菜单、加载中的音频、全屏、浏览器声音授权 | 重新建立；不会恢复后自动取得声音授权 |

两人同时点不同的歌都会保留；普通点歌同时点中同一来源时只入队一次。需要重复演唱可从「已唱」再点。调序会校验旧状态，过期操作不会覆盖新歌单。播放、暂停、拖动进度、切歌、混音和升降调只影响当前浏览器；其他设备仍可继续演唱。切歌结束操作在浏览器持久保存，服务器确认前显示“等待同步移除”；临时断线后自动补发，刷新和换标签也不会丢失，重复确认不会重复写入已唱。同一浏览器切换标签页不会恢复旧歌曲；在另一个标签页操作播放控件时移交播放，原标签停止发声。暂停或恢复页面时，已从待唱移除的选曲回到队首；正在另一台设备演唱的歌曲可继续唱完。

### 点歌与播放

首页顶部居中突出搜索栏，滚动时也可直接搜歌。点左上角退学 KTV回到主页面并聚焦搜索；点击当前曲目的封面、歌名或底部歌曲区域直接回到播放页并滚到顶部，保留播放进度。曲库采用与搜索一致的紧凑歌曲行，点歌与找 MV 分开。首页及语言分类只展示已完成、文件齐全的歌曲，默认选中「全部」，每页12首，页码随当前标签页保存；演唱记录在「已唱」tab 中查看并再点。其他歌曲的歌名与封面都进入同一个预览；专辑、歌手保留自己的浏览入口，播客等其他类型在原站打开，不当作歌曲提交。

1. 输入歌名／歌手，停顿 700 ms 或按回车／「搜索」。默认「综合」展示 YouTube Music 原生搜索的歌曲、专辑、歌手等结果，不额外匹配标题或筛选类型；专辑可点开逐首点歌；切换「歌手」后直接展示 YouTube Music 首个歌手结果的曲目；有其他结果时，可用头像旁的「其他歌手」切换，候选列表继续按需分页。也可点击单曲的歌手署名进入。默认歌曲在前、专辑其次，其余类型随后；各类保留平台顺序，歌曲中明确标注的现场版靠后，专辑内保留曲目顺序；也支持播放量、已准备优先和歌名排序；播放量只排序已加载结果，未提供计数时不可选择。
   歌曲可以预览并「点歌」；专辑明确标注「专辑」，通过「查看专辑」进入曲目列表，保留专辑与单曲的区别。已读取的专辑曲目复用；「返回上一级」及浏览器后退恢复之前的结果、排序和滚动位置，刷新保留当前搜索页面。「找 MV」进入该歌曲的 YouTube 视频搜索。「YouTube 视频」保留原始整页搜索，「本地」只查看已有曲库。本地已准备歌曲预览缓存 MV，加入时复用现有任务。
   歌曲入队后立即出现在待唱列表，保留准备进度与失败提示；完成且文件齐全后才进入曲库。曲库、搜索结果和待唱列表不重复显示「可直接唱」「待补视频」等静态就绪标签。已在待唱中的来源显示「已点」，避免重复提交；从已唱记录主动再点时可复用同一个处理任务。语言分类依次为华语／粤语／英语／日语／韩语／小语种，粤语独立显示；已知的其他语言归入「小语种」，未知时先留在「全部」。粤语歌词在汉字上方显示粤拼，日文汉字显示平假名，均在准备视频时生成，不增加播放设备计算。曲库只包含音轨和视频均可播放的歌曲，不包含待补视频、排队和失败任务。
2. 也可以直接粘贴 YouTube 单个视频链接，可填写歌名，点击「点歌」。
   从搜索结果点歌后立即显示视频标题；下载和歌词整理继续更新歌名、歌手。搜索标题不覆盖后续识别结果，手动填写的歌名仍优先。
   准备时，待唱列表与播放页显示各个步骤的实时进度，以及从本次实际开始处理起累计的「已用时」；排队不计时，切换步骤或刷新页面不归零，重试从本次开始时间重新计时。百分比来自实际已完成工作量；无法取得总量的步骤只显示状态，下载则保留已下载大小。并行步骤分开显示。
3. 点歌只加入待唱队列；成功后按钮禁用并显示「已点」和待唱位置，底部反馈可直接查看待唱。播放统一用底部播放按钮或播放页的「开始唱」，首次点击会启用当前浏览器声音。
   本浏览器按过播放后会继续接唱：歌单暂时为空或歌曲尚未准备好时保留播放意图，待唱中有歌曲就绪就自动接上。主动暂停会取消接唱；仅点歌的其他浏览器不会因此发声。播放意图与进度在同一浏览器共享，刷新后仍需浏览器允许声音启动，音轨与画面就绪前不推进时钟。
4. 右侧歌单分为「待唱」和「已唱」。待唱包含当前歌曲及所有排队歌曲，包括未开始准备和正在处理的歌；每首歌下方直接提供置顶和移除，不需要展开菜单。置顶时若本机正在唱的歌仍在队列中，就排在它后面，否则排到第一；其余歌曲保持相对顺序，不打断其他设备正在演唱的歌曲。尚未开始演唱时，播放器预选同步到队首；已经开始或手动定位的演唱即使暂停，也保留当前曲目、位置和调号。失败或等待自动重试的歌曲直接提供「重试」，播放页的错误下方也提供相同入口；手动重试取消应用自身的等待，仍遵守视频站点的限流。已有成品不再显示「重新准备」入口，直接复用缓存。调整顺序同时改变未开始的预处理优先级，旧版服务端播放字段不参与这个顺序。
   移除未完成歌曲的最后一个待唱条目，会停止它的全部后台处理并取消自动重试。已经完成的阶段保留，再次点歌时从可复用的检查点继续；半成品不会显示为已准备。若还有其他人点着同一任务，处理继续。已完成的歌曲仍保留缓存，移出歌单不等于删除成品。
   已唱按来源展示最后一次演唱，按时间倒序显示，可按歌名或歌手搜索，点击「再点」加入待唱队尾并复用现有缓存。真正开始播放的歌曲在切歌、唱完或移除时留下一条历史；仅在等待或开场倒计时中跳过的歌不计入。同一首唱多次仍在服务端保留多次记录，列表按来源去重。历史在服务端持久保存，刷新或重启不丢失，也不占用待唱队列位置或保护媒体免于正常缓存回收。历史从此功能上线后开始记录，之前已移除的条目无法重建演唱顺序。
5. 普通页面和全屏都在底部提供「下一首」。唱完自动进入下一首；若下一首尚未准备好则等待，可再次切歌跳过。加载完成才开始计算播放时间。

歌曲搜索只在点歌台显示。切到播放页或待唱页不显示搜索框，回到点歌台保留之前的关键词和搜索结果。

底部常驻播放／暂停、重唱、下一首、主唱音量与升降调，浏览点歌页时也能直接操作。播放器另提供全屏。快捷键：空格暂停／继续，`N` 下一首，`F` 全屏；输入文字时不会触发。

较长前奏播放时，画面左上角显示「跳过前奏」；进入全屏后，按钮移到下方 panel 的播放控制旁。点击跳到本首成品的三点准备提示开始处，保留完整四秒准备节奏；点击跳过或自然播放到该位置后，按钮自动消失。手机和电脑使用同一个按钮，定位后保持音量和调号，音画加载好再继续。前奏不足五秒或没有对应成品的提示时间时不显示按钮。

曲库、搜索结果、预览和链接点歌成功后，原位显示禁用的「已点」及待唱位置，随队列调整更新，不重复加入；播放和准备进度在正在播放或待唱页查看。移出待唱后恢复「点歌」，需要重复演唱可在「已唱」中使用「再点」。点歌请求失败后可直接重试。

搜索与下载得到的来源封面立即保存并显示，排队、处理中和重试都可见，不等整首完成。成品优先使用本地封面，获取不到时截取 MV 画面；没有可用图片才显示占位图，封面失败不阻止歌曲准备。本地封面随歌曲纳入缓存上限与 LRU 回收，浏览封面不会刷新歌曲的最近播放／使用时间。

歌手页没有歌曲栏目时，显示该歌手的视频列表；连视频也没有时显示其专辑和单曲发行，点击进入选曲。标题相应显示「歌手视频」或「歌手作品」，不把未提供的歌曲栏目当成整位歌手没有作品。

片头信息过长时省略显示，数据或字体不可用时只省略片头并记录原因；下一句预读过长时也可省略，唱到该句仍显示完整歌词。简介解析与其他歌词来源一样单独处理错误，不能抹掉其他来源已返回的有效歌词。

全屏复用同一套底部播放控件，保留播放／暂停、重唱、下一首、主唱音量和两个升降调按钮。全屏保留主唱百分比加减按钮和唯一的播放进度滑杆；整体音量固定 100%，通过设备音量调节响度；退出后控件回到原位，声音与进度不中断。

播放时优先用浏览器实际呈现帧的时间检查音画同步，避免视频进度的瞬时错误读数触发整首暂停重启。画面隐藏或浏览器未提供近期呈现帧时使用视频自身时钟；真正停住或明显失步时仍会等待音画共同就绪。

系统短暂中断声音时，音画和播放进度一起停住，保留继续播放的意图。只有声音上下文真正恢复运行后，才从停住的位置自动续播；期间主动暂停、定位、换歌或移交标签页，会使旧的恢复操作失效。浏览器明确拒绝声音权限时仍需点播放重试。预览遵循相同规则。

播放控件只在显示内容变化时更新：进度滑杆按已有的 0.1 秒精度移动，时间文字每秒变化，片头圆点按节拍切换。加载提示和按钮不随每个画面帧重复改写；音画调度仍使用原来的精确时钟。

首页曲库、语言分类、综合搜索上方的「曲库里的歌」和「本地曲库」搜索只显示已完成、文件齐全的歌曲。回收缓存后不再显示为本地歌曲；准备进度仍在待唱队列，已唱记录和来源信息保留。

搜索读取音乐／视频元数据，并为当前可见歌曲检查已发表歌词；不下载音视频、不创建预处理任务，点歌才开始准备。歌曲、歌手、歌手热门列表和 YouTube 视频搜索按平台原生分页加载，滚到列表末尾自动追加下一页，也可点击「加载更多」。显示「已加载」数量，到底后停止；加载失败保留已有结果并提供重试，搜索过期时可重新搜索。切换关键词或歌手会取消旧请求；保留不同版本和同名歌手。歌手搜索自动展开首个结果，不按搜索词再次匹配名字；其他候选仍可切换。已展开的歌手曲目、候选及分页随本标签页历史保存，返回与刷新会复用。热门顺序来自 YouTube Music 歌手页，不代表 KTV 点唱统计。「YouTube 视频」同样保留平台顺序，仅将明确标注的现场版后置，不按关键词、认证、类型额外筛选，也没有 3 条限制。失败可重试，空结果与搜索失败分别显示。预览使用官方嵌入播放器，不自动播放；有些视频不允许嵌入，可用旁边的原站链接观看。

### 主唱音量

伴奏和伴唱始终开启；主唱标签为「主唱：开／关」按钮，关闭立即归零，开启恢复最近一次非零百分比；没有历史设置时开启为 100%。旁边保留「−／＋」按钮，每次减小／增大 5 个百分点，范围 0–100%，默认 0%。播放音轨共用一个 AudioContext，按钮只调节主唱增益，不重启歌曲。旧版本保存的伴奏、伴唱音量恢复为 100%，主唱保留原百分比；切歌和刷新保留当前浏览器共享的音量，其他设备不会改变它。

普通和全屏视图均不提供整体音量滑杆，网页增益固定 100%，用设备音量控制响度；旧版保存的网页音量会清除。普通点歌长期保存底轨与主唱两轨 24-bit FLAC；临时 float64 音轨在成功后回收。独立严格音频验收仍保留三轨母版。

### 实时升降调

底栏的 `♭` / `♯` 每次降低／升高一个半音，中间仅显示当前值，不是按钮。范围 -6 至 +6；普通视图与全屏均可操作。每次换歌、自动接唱或重唱回到原调（0）；同一首歌暂停后继续、定位或刷新页面保留当前调值，其他设备独立。

底轨与主唱混合后共同经过本地 Signalsmith Stretch AudioWorklet，不改变播放速度，不重新下载或生成音轨，主唱仍可随时调节百分比。原调使用带等量延迟的原始音频通道，原调或暂停时跳过变调 DSP；启用升降调时恢复处理，切换时短暂交叉淡化。当前 160 ms 分析窗带来 200 ms 处理延迟，播放页的视频、亮字与进度使用补偿后的可听时间，避免字幕领先。暂停或定位时关闭输出并清除处理器里的旧音频。

升降调需要 AudioWorklet，并通过 localhost 或 HTTPS 打开；同一 Wi-Fi 平板通过普通 HTTP 仍可原调播放。升降调测试覆盖双声道三音混合、0 / +3 / -2 / +6 / -6 动态变调和处理延迟；音质评测方法见[验收标准](ACCEPTANCE.md)。

### 本地缓存上限

在歌单底部展开 **本地缓存**，可看当前占用、修改容量上限。默认 **10 GiB**，设置保存后立即应用并持久化。初次部署也可用 `KARAOKE_CACHE_MAX_GIB` 指定默认值；已有设置以数据库中保存的值为准。

独立计算服务器可以通过 `POST /v1/storage` 设置 `limit_gib: null` 取消应用配额，或在空数据目录初次启动时设置 `KARAOKE_CACHE_MAX_GIB=none`。返回的 `limit_bytes` 为 `null`，页面显示「不限」。该设置只作用于当前服务的数据目录。没有应用配额时仍检查实际磁盘余量、预留运行空间并保护待唱及正在使用的文件。

- 容量包括服务管理的歌曲下载、预处理中间文件和成品。音轨与字幕完整后即保留成品、源文件和必要诊断，清理解码、分离及封装中间音频，不等待 MV 完成；失败待重试时保留已完成阶段，明确重新准备时允许重跑分离。这些文件全部计入同一个缓存上限。
- 从已唱记录或本地曲库再次点歌，直接使用选中的完整成品，不因服务升级而重新处理；保留其真实处理版本。明确重新准备才运行当前算法，重播不会被算作新算法验收通过。
- 可信歌词原文也随任务保存。普通准备会复用来源、元数据、选取时长、元数据模型、检索实现和用户填写信息均匹配的歌词缓存；缓存失效、缺失或明确重新准备时才重新联网查找。缓存只复用正文，仍须完成声学对齐与产物校验。
- 超过预算时，先清理未受保护任务的无用中间文件，再按最近使用时间回收可恢复的字幕 MV，保留计算过的底轨、主唱、字幕时间轴和封面；仍不够才按 LRU 回收整首歌。点歌、播放和读取媒体会刷新使用时间；浏览曲库不会。
- 正在处理、仍在待唱列表、正在通过 HTTP 下载的歌曲受保护。实际启用过播放、且持有发声权的标签页通过 SSE 保护当前歌曲；暂停和另一端从队列移除不会提前解除。仅浏览时自动选中的歌曲不额外持有播放保护。
- 仅回收视频的歌曲不再显示在可播放曲库中，歌曲信息与已唱记录仍保留。再次点歌复用同一任务，只下载原视频、核对音频指纹、用保留的音轨和时间轴重新合成字幕 MV，不调用分离、ASR 或对齐模型。仍需下载和视频编码的时间。补视频失败保留音轨和字幕，可重试；若来源音频已改变，明确报错，不能把旧时间轴套到新版本。
- 完整回收后仍保留歌曲信息，下次点歌需要重新准备。不具备恢复元数据的旧缓存只能完整回收。
- 空间不足以容纳受保护歌曲时，禁止把上限降到其占用以下。新任务准备空间不足时会明确失败，可移除待唱歌曲或释放空间后重试。
- 预处理期间每秒检查预算，预留最多 256 MiB 写入余量及 1 GiB 系统可用空间；超额时终止该任务并清理临时文件。这是应用级预算，突发写入可能短暂超额，不是文件系统硬配额。

这个上限只管理 `KARAOKE_DATA_DIR` 中的任务歌曲文件；模型权重、旧实验目录和 SQLite 元数据不计入，也不会自动删除。

### 手机与电脑同时使用

所有设备都打开同一个网页，点播放就在当前设备发声。旧的 `/?remote=1` 链接也使用相同行为，不需要选择播放或遥控模式。

默认只监听本机。若明确需要同一局域网内的手机访问，可以启动：

```sh
KARAOKE_HOST=0.0.0.0 .venv/bin/python -m karaoke.api
```

手机访问 `http://电脑局域网IP:8746/`。这是单房间应用，未实现账号和独立房间，局域网中可访问该地址的人都能操作同一歌单。

## 状态与恢复

### 准备失败后继续

待唱列表和播放页会显示错误原因与「重试」入口。重试沿用原任务，复用已校验的下载、音轨和阶段结果；已完成歌曲可以直接复用。移除未完成歌曲的最后一个待唱条目会停止后台处理，再次点歌时从有效检查点继续。

| 遇到的问题 | 处理方式 |
| --- | --- |
| 临时断网、下载超时、单个视频返回 403 | 自动重试最多三次，通常等待 5、20、80 秒；页面显示「等待自动重试」 |
| 来源返回 429 限流 | 按来源要求等待，至少一分钟；需要更久时使用服务端给出的期限 |
| 登录验证、视频下架或配置错误 | 按错误提示完成登录、选择可访问的版本或修正配置，再点「重试」 |
| 找不到完整歌词 | 尝试搜索中的「有歌词」版本，或通过 [API 的 lyrics 参数](API.md#可选参数)提供与录音一致的歌词 |
| 缓存或磁盘空间不足 | 释放磁盘空间，或在磁盘允许时调大歌曲缓存上限，再重试 |
| 新歌一直排队，当前没有任务在处理 | 按 [运行配置](../SETUP.md#5-运行配置)检查服务是否保留了维护暂停状态 |

自动重试的次数与期限会持久保存，刷新或重启后继续。等待期间释放处理工位，其他可运行的步骤继续执行。手动重试取消应用自身的等待，来源平台的限流期限仍然生效。

### 歌词与字幕

准备流程从 LINE MUSIC、LRCLIB、网易云、LyricsWeb、YouTube Music 和视频简介等来源查询已发表歌词；日文还会查询带注音的 UtaTen 页面。先核对歌曲身份，再交叉比较正文，优先采用多个来源一致的版本。时间轴由当前录音重新对齐生成；来源、正文差异和录音版本差异保存在任务诊断中。

找不到完整歌词或仍有歌词行无法定位时，页面显示失败并保留音轨、可用字幕和诊断。局部字词边界仍不明确时，可按已有边界以词组扫亮，回退范围记录在诊断里。对齐规则与测量方法见[字幕设计](docs/design/subtitles.md)和[验收标准](ACCEPTANCE.md)。

### 成品与缓存

音轨、完整字幕和 MV 校验完成后，歌曲进入曲库。封面缺失时尝试截取视频画面，片头信息无法显示时省略片头；这些辅助展示独立处理。视频被缓存回收后，再点歌会复用音轨和字幕补回视频；补视频失败仍保留原音轨，可继续重试。

详细的阶段依赖、存储格式和恢复规则见[处理与存储流程](docs/processing.md)及 [API](API.md)。

### 平板播放

播放页按需读取现有母版的 8 秒片段，统一应用成品的防削波增益，以 24-bit FLAC 传输；保留原采样率与声道，不重跑分离、歌词、对齐或视频渲染。服务器只做短段读取和 CPU 压缩，不调用 GPU。旧任务已有的 MP3 仍可下载，新普通任务不再生成。

客户端先加载当前段即可开唱，只向前缓冲附近片段，不因打开页面而下载整首音频或视频。暂停会取消未完成加载；已下载的压缩音频可供恢复、定位和重唱复用，当前段及随后约 24 秒才解码。临时网络错误自动退避重试，切歌会取消旧下载。全部音轨按同一个 AudioContext 时钟调度，段边界带有重采样余量，播放时裁掉重叠部分。一轨仍未到齐时先播完已有音频，再一起等待，本机时钟冻结在共同边界，加载完成后恢复。视频保持原生速度，缓冲状态短暂下降但画面仍推进时不打断声音；实际停滞或明显失步时才暂停并重新就绪。网络持续中断时会停在已缓冲片段的末尾，音画重新就绪后继续。

### 点歌前查看歌词

综合搜索、歌手作品、专辑曲目和 YouTube 视频结果都会在歌名下显示「歌词待查」「有歌词」或「歌词未确认」，手机上同样可见。可选择「有歌词优先」重排已加载结果，不删除其他版本。

「有歌词」表示已从 YouTube Music 读取对应录音的已发表歌词正文，并排除标题、署名和明显过短的残片；点歌后继续核对完整正文并生成时间轴。「歌词未确认」包括该来源未收录、时长不足以判断和网络暂不可用，正式准备会继续尝试其他歌词来源。

只检查当前可见歌曲，合并批量请求，返回与刷新复用未过期结果。来源查询有全局并发和数量上限；相同录音由所有浏览用户共享一次查询和有时效的缓存。检查结果不会写入房间、推进播放或改变待唱顺序。
