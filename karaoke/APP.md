# 余音 · 网页卡拉 OK

## 运行

从工作区根目录启动：

```sh
.venv/bin/python -m karaoke.api
```

打开 <http://127.0.0.1:8746/>。网页与 API 由同一个服务提供，不需要 Node 构建或额外前端服务器。依赖沿用 [API.md](API.md)。

## 使用

### 多人使用时的状态

| 范围 | 包含的状态 | 刷新后 |
|---|---|---|
| 房间共享 | 待唱顺序、已唱记录、准备状态、缓存上限 | 从服务端重新同步，所有人一致 |
| 当前浏览器标签页 | 搜索词、搜索类型、结果与分页、排序、语言筛选、正在浏览的页面、待唱／已唱 tab、历史筛选、主页面滚动位置、本机选曲、播放位置、主唱音量、升降调 | 恢复各自的状态，播放保持暂停直至点击；前进／后退不改变音量 |
| 临时交互 | 预览弹窗、展开菜单、加载中的音频、全屏、浏览器声音授权 | 重新建立；不会恢复后自动取得声音授权 |

两人同时点不同的歌都会保留；普通点歌同时点中同一来源时只入队一次。需要重复演唱可从「已唱」或「最近唱过」再点。调序会校验旧状态，过期操作不会覆盖新歌单。播放、暂停、拖动进度、切歌、混音和升降调只影响操作的设备；其他设备仍可继续演唱。一个设备唱完并移除共享待唱条目后，另一台正在唱同一首的设备仍保留自己的歌曲和媒体。

### 点歌与播放

首页顶部居中突出搜索栏，滚动时也可直接搜歌。点左上角余音回到主页面并聚焦搜索；点击当前曲目的封面、歌名或底部歌曲区域直接回到播放页并滚到顶部，保留播放进度。曲库采用与搜索一致的紧凑歌曲行，点歌与找 MV 分开。首页默认展示「可直接唱」的歌曲，保留全部与语言分类；曲库下方的「最近唱过」可预览并再点，没有演唱历史时不显示。其他歌曲的歌名与封面都进入同一个预览；专辑、歌手保留自己的浏览入口，播客等其他类型在原站打开，不当作歌曲提交。

1. 输入歌名／歌手，停顿 700 ms 或按回车／「搜索」。默认「综合」展示 YouTube Music 原生搜索的歌曲、专辑、歌手等结果，不额外匹配标题或筛选类型；专辑可点开逐首点歌；切换「歌手」后直接展示 YouTube Music 首个歌手结果的曲目；有其他结果时，可用头像旁的「其他歌手」切换，候选列表继续按需分页。也可点击单曲的歌手署名进入。默认歌曲在前、专辑其次，其余类型随后；各类保留平台顺序，歌曲中明确标注的现场版靠后，专辑内保留曲目顺序；也支持播放量、已准备优先和歌名排序；播放量只排序已加载结果，未提供计数时不可选择。
   歌曲可以预览并「点歌」；专辑明确标注「专辑」，通过「查看专辑」进入曲目列表，保留专辑与单曲的区别。已读取的专辑曲目复用；「返回上一级」及浏览器后退恢复之前的结果、排序和滚动位置，刷新保留当前搜索页面。「找 MV」进入该歌曲的 YouTube 视频搜索。「YouTube 视频」保留原始整页搜索，「本地」只查看已有曲库。本地已准备歌曲预览缓存 MV，加入时复用现有任务。
   歌曲入队后立即出现在曲库，保留准备进度与失败提示；曲库、搜索结果、最近唱过和待唱列表不重复显示「可直接唱」「待补视频」等静态就绪标签。正在处理的歌也可以再点一次，复用同一个处理任务。语言分类依次为华语／英语／日语／韩语／小语种，已知的其他语言归入「小语种」，未知时先留在「全部」；「可直接唱」只包含音轨和视频均可播放的歌曲，不包含待补视频、排队和失败任务。
2. 也可以直接粘贴 YouTube／Bilibili 单个视频链接，可填写歌名，点击「点歌」。
   从搜索结果点歌后立即显示视频标题；下载和歌词整理继续更新歌名、歌手。搜索标题不覆盖后续识别结果，手动填写的歌名仍优先。
   准备时，曲库、歌单与播放页显示各个步骤的实时进度，以及从本次实际开始处理起累计的「已用时」；排队不计时，切换步骤或刷新页面不归零，重试从本次开始时间重新计时。百分比来自实际已完成工作量；无法取得总量的步骤只显示状态，下载则保留已下载大小。并行步骤分开显示。
3. 点歌后原位显示「开始唱」或「查看进度」，并显示待唱位置；底部反馈也有相同入口。「开始唱」直接在当前设备播放。待唱列表常驻开唱按钮，底部播放按钮仍可用。首次点击会启用浏览器声音。
   本浏览器按过播放后会继续接唱：歌单暂时为空或歌曲尚未准备好时保留播放意图，待唱中有歌曲就绪就自动接上。主动暂停会取消接唱；仅点歌的其他浏览器不会因此发声。播放意图与进度随本标签页保存，刷新后仍需浏览器允许声音启动，音轨与画面就绪前不推进时钟。
4. 右侧歌单分为「待唱」和「已唱」。待唱包含当前歌曲及所有排队歌曲，包括未开始准备和正在处理的歌；歌曲准备完成后可直接点「开始唱」；每首歌下方直接提供置顶和移除，不需要展开菜单。置顶时若本机正在唱的歌仍在队列中，就排在它后面，否则排到第一；其余歌曲保持相对顺序，不改变任何设备的播放进度。失败或等待自动重试的歌曲直接提供「重试」，播放页的错误下方也提供相同入口；手动重试取消应用自身的等待，仍遵守视频站点的限流。已有成品提供「重新准备」，创建独立的新任务并复用可验证的来源下载；旧成品不被覆盖，正在唱旧成品的设备不受影响。调整顺序同时改变未开始的预处理优先级。
   已唱按最近一次唱过的顺序倒序显示，可按歌名或歌手搜索，点击「再点」加入待唱队尾并复用现有缓存。真正开始播放的歌曲在切歌、唱完或移除时留下一条历史；仅在等待或开场倒计时中跳过的歌不计入。同一首唱多次会保留多次记录。历史在服务端持久保存，刷新或重启不丢失，也不占用待唱队列位置或保护媒体免于正常缓存回收。历史从此功能上线后开始记录，之前已移除的条目无法重建演唱顺序。
5. 普通页面和全屏都在底部提供「下一首」。唱完自动进入下一首；若下一首尚未准备好则等待，可再次切歌跳过。加载完成才开始计算播放时间。

歌曲搜索只在点歌台显示。切到播放页或待唱页不显示搜索框，回到点歌台保留之前的关键词和搜索结果。

底部常驻播放／暂停、重唱、下一首、主唱音量与升降调，浏览点歌页时也能直接操作。播放器另提供全屏。快捷键：空格暂停／继续，`N` 下一首，`F` 全屏；输入文字时不会触发。

曲库、搜索结果、预览和链接点歌成功后，原位显示待唱位置及「开始唱／查看进度」，随队列调整更新；已在待唱中的歌曲点击时打开播放或准备进度，不会重复加入。移出待唱后恢复「点歌」，需要重复演唱可在「已唱」中使用「再点」。点歌请求失败后可直接重试。

搜索与下载得到的来源封面立即保存并显示，排队、处理中和重试都可见，不等整首完成。成品优先使用本地封面，获取不到时截取 MV 画面；没有可用图片才显示占位图，封面失败不阻止歌曲准备。本地封面随歌曲纳入缓存上限与 LRU 回收，浏览封面不会刷新歌曲的最近播放／使用时间。

歌手页没有歌曲栏目时，显示该歌手的视频列表；连视频也没有时显示其专辑和单曲发行，点击进入选曲。标题相应显示「歌手视频」或「歌手作品」，不把未提供的歌曲栏目当成整位歌手没有作品。

片头信息过长时省略显示，数据或字体不可用时只省略片头并记录原因；下一句预读过长时也可省略，唱到该句仍显示完整歌词。简介解析与其他歌词来源一样单独处理错误，不能抹掉其他来源已返回的有效歌词。

全屏复用同一套底部播放控件，保留播放／暂停、重唱、下一首、主唱音量和两个升降调按钮。全屏保留主唱百分比加减按钮和唯一的播放进度滑杆；整体音量固定 100%，通过设备音量调节响度；退出后控件回到原位，声音与进度不中断。

搜索只读取音乐／视频元数据，不下载完整视频、不创建预处理任务；点歌才开始准备。歌曲、歌手、歌手热门列表和 YouTube 视频搜索按平台原生分页加载，滚到列表末尾自动追加下一页，也可点击「加载更多」。显示「已加载」数量，到底后停止；加载失败保留已有结果并提供重试，搜索过期时可重新搜索。切换关键词或歌手会取消旧请求；保留不同版本和同名歌手。歌手搜索自动展开首个结果，不按搜索词再次匹配名字；其他候选仍可切换。已展开的歌手曲目、候选及分页随本标签页历史保存，返回与刷新会复用。热门顺序来自 YouTube Music 歌手页，不代表 KTV 点唱统计。「YouTube 视频」同样保留平台顺序，仅将明确标注的现场版后置，不按关键词、认证、类型额外筛选，也没有 3 条限制。B站不再参与搜索。失败可重试，空结果与搜索失败分别显示。预览使用官方嵌入播放器，不自动播放；有些视频不允许嵌入，可用旁边的原站链接观看。

### 主唱音量

伴奏和伴唱始终开启；主唱使用「−／＋」按钮，每次减小／增大 5 个百分点，范围 0–100%，默认 0%。三条音轨共用一个 AudioContext，按钮只调节主唱增益，不重启歌曲。旧版本保存的伴奏、伴唱音量恢复为 100%，主唱保留原百分比；切歌和刷新保留本标签页的音量，其他设备不会改变它。

普通和全屏视图均不提供整体音量滑杆，网页增益固定 100%，用设备音量控制响度；旧版保存的网页音量会清除。原始 float64 三轨母版仍可通过 API 下载；本轮只精简网页操作，不改动分离或字幕结果。

### 实时升降调

底栏的 `♭` / `♯` 每次降低／升高一个半音，中间仅显示当前值，不是按钮。范围 -6 至 +6；普通视图与全屏均可操作。每次换歌、自动接唱或重唱回到原调（0）；同一首歌暂停后继续、定位或刷新页面保留当前调值，其他设备独立。

三个声部混合后共同经过本地 Signalsmith Stretch AudioWorklet，不改变播放速度，不重新下载或生成音轨，主唱仍可随时调节百分比。原调使用带等量延迟的原始音频通道，原调或暂停时跳过变调 DSP；启用升降调时恢复处理，切换时短暂交叉淡化。当前 160 ms 分析窗带来 200 ms 处理延迟，播放页的视频、亮字与进度使用补偿后的可听时间，避免字幕领先。暂停或定位时关闭输出并清除处理器里的旧音频。

升降调需要 AudioWorklet，并通过 localhost 或 HTTPS 打开；同一 Wi-Fi 手机通过普通 HTTP 仍可原调播放。数值测试覆盖双声道三音混合、0 / +3 / -2 / +6 / -6 动态变调和处理延迟，不代替整首歌曲的主观音质验收。

### 本地缓存上限

在歌单底部展开 **本地缓存**，可看当前占用、修改容量上限。默认 **10 GiB**，设置保存后立即应用并持久化。初次部署也可用 `KARAOKE_CACHE_MAX_GIB` 指定默认值；已有设置以数据库中保存的值为准。

独立计算服务器可以通过 `POST /v1/storage` 设置 `limit_gib: null` 取消应用配额，或在空数据目录初次启动时设置 `KARAOKE_CACHE_MAX_GIB=none`。返回的 `limit_bytes` 为 `null`，页面显示「不限」。该设置只作用于这台服务；Mac 仍可保持 10 GiB。没有应用配额时仍检查实际磁盘余量、预留运行空间并保护待唱及正在使用的文件。

- 容量包括服务管理的歌曲下载、预处理中间文件和成品。完成后保留成品、源文件、两次分离的检查点和少量诊断，清理可重新生成的解码及封装中间音频；以后更新字幕可复用输入和模型仍匹配的分离结果。这些文件全部计入同一个缓存上限。
- 从已唱记录或本地曲库再次点歌，直接使用选中的完整成品，不因服务升级而重新处理；保留其真实处理版本。明确重新准备才运行当前算法，重播不会被算作新算法验收通过。
- 超过预算时，先按最近使用时间回收可恢复的字幕 MV，保留计算过的三条音轨、试听音频、字幕时间轴和封面；视频都回收后仍不够，再按 LRU 回收整首歌。点歌、播放和读取媒体会刷新使用时间；浏览曲库不会。
- 正在处理、仍在待唱列表、正在通过 HTTP 下载的歌曲受保护。任一设备当前选中的歌曲通过 SSE 连接保留缓存保护，直到切换歌曲或关闭页面；暂停和另一端从队列移除也不会提前解除。
- 仅回收视频的歌曲仍保留在曲库。再次点歌复用同一任务，只下载原视频、核对音频指纹、用保留的音轨和时间轴重新合成字幕 MV，不调用分离、ASR 或对齐模型。仍需下载和视频编码的时间。补视频失败保留音轨和字幕，可重试；若来源音频已改变，明确报错，不能把旧时间轴套到新版本。
- 完整回收后仍保留歌曲信息，下次点歌需要重新准备。不具备恢复元数据的旧缓存只能完整回收。
- 空间不足以容纳受保护歌曲时，禁止把上限降到其占用以下。新任务准备空间不足时会明确失败，可移除待唱歌曲或释放空间后重试。
- 预处理期间每秒检查预算，预留最多 256 MiB 写入余量及 1 GiB 系统可用空间；超额时终止该任务并清理临时文件。这是应用级预算，突发写入可能短暂超额，不是文件系统硬配额。

这个上限只管理 `KARAOKE_DATA_DIR` 中的任务歌曲文件；模型权重、旧实验目录和 SQLite 元数据不计入，也不会自动删除。

### 手机与电脑同时使用

所有设备都打开同一个网页，点播放就在当前设备发声。旧的 `/?remote=1` 链接也使用相同行为，不需要选择播放或遥控模式。

默认只监听本机。若明确需要同一局域网内的手机访问，可以启动：

```sh
KARAOKE_HOST=0.0.0.0 .venv/bin/python -m karaoke.api
```

手机访问 `http://电脑局域网IP:8746/`。这是单房间应用，未实现账号和独立房间，局域网中可访问该地址的人都能操作同一歌单。

## 状态与恢复

下载临时失败会自动重试，最多三次。连接中断、超时、服务端临时错误及单个视频的 403，三次分别等待 5、20、80 秒；明确的 429 限流从一分钟起翻倍，有服务端重试时间时遵守更晚的期限。登录验证、不可访问及配置错误不会盲目重试。等待期间显示「等待自动重试」，不占用处理工位，其他可处理歌曲继续准备。计时和次数随任务保存，刷新网页或重启服务不会重置。重试复用已校验的下载、音轨与阶段结果，不新增点歌项；移除最后一个引用该任务的待唱条目后停止后续自动重试。

明确的 429 对同一视频来源共享退避，包括已经启动但尚未取得下载工位的歌曲；其他来源继续。登录验证、视频下架或配置错误仍需处理原因后手动重试，不会靠无限重试解决。下载重试不会重跑未修复的字幕或音轨校验失败。

封面、片头和下一句预读属于附属展示：封面缺失不会使已完成歌曲失效或阻止复用音轨，片头失败只省略片头，预读超宽只缩略预读。错误保留在日志或渲染报告中。当前句歌词、音轨、来源一致性、完整解码和实际缓存空间仍属于准备完成的必要条件，不能因附属展示的回退而跳过。

日常点歌并行查询 LINE MUSIC、LRCLIB、网易云和同一视频的 YouTube Music 歌词；视频简介中明确发布的歌词可作为第五路候选。先匹配歌名、歌手和版本，再交叉比较正文。比较时忽略署名、繁简体、标点与换行，保留词序和重复唱段；至少两个不同来源的全文一致、且没有同票数的冲突组时优先采用其中一份原文；否则保留可信来源原文与差异，继续由声学模型对齐，不拼接不同版本。已知同一歌词出版方只计一次；不同网站仍可能互相转载，因此一致只是文本证据，不保证录音版本或起音准确。来源链接、文本哈希及差异保存在 `lyric-crosscheck.json`，单站不可用不影响其他站点，登录限制和 429 退避会跨任务保留。完全找不到可用文本时保留音轨与诊断并报错，不采用猜测稿。视频标题中的明确歌手／曲名署名可直接用于检索，上传者不冒充歌手。用户提供或已核对的歌词保持原有入口。

若来源缺少可靠歌手署名、Music 只返回上传频道，且现有查询没有歌词，再按歌名查正式歌曲目录。候选须歌名匹配、时长接近；不同歌手的候选时长无法区分时保留歧义，不直接选首项。用候选署名重新查询已发表歌词，并沿用来源交叉比较和完整声学对齐；单个可靠来源仍可作为待对齐候选。目录回退记录为身份恢复诊断，不覆盖用户或来源已明确提供的歌手，不把目录时长当成字幕时间。

公开歌词开头与元数据完全对应的「歌手 - 歌名」或「歌名 - 歌手」属于署名标题，在排版前移除并记录原行号；已知译名同样适用。单独出现的歌名、正文中再次出现的相同文字，以及不能核对身份的短语仍保留，避免把真正唱到的歌词误删。

中英文并列、英文在前和括号内的译名都参与歌词身份匹配；已知歌名／歌手时仍检查简介中的歌词。优先选择同一录音，找不到时允许同曲同歌手的录音室或其他现场版本提供纯文本，时长、现场地点等差异记入 `recording_mismatches` 和统计中的 soft fail；只对当前音频重新对齐，不采用其他版本的时间戳。严格 ASR 验收仍保留原录音及覆盖校验。全文未完全一致时，至少三个不同出版方的相近正文可优先于孤立候选，但状态仍是有差异，不算全文核对通过，也不拼接歌词。

已知录音的专辑和时长参与歌词候选排序：同曲同歌手先匹配版本，再优先同一发行专辑和最接近的时长，避免把重录版新增的旁白套到原版。缺少发行信息时保持可用来源回退；优先候选没有完整歌词时继续检查下一份，不因专辑不同直接丢弃正文，也不采用来源时间戳。

找不到可靠歌词时保留音轨和诊断，任务报错，不再用 ASR 猜测稿生成字幕。“纯音乐，请欣赏”“暂无歌词”等整份占位文案不作为歌词；继续检查同来源的后续候选，网页实体还原后再处理正文。

直接对齐出现坏句时，只重试连续坏句及相邻的有效句，音频窗口不超过 45 秒，每块最多 8 次；候选必须文字完整、时间有效且不与保留的邻句冲突，只替换坏句。没有邻句定位或窗口过长时保留原因，供进一步诊断。逐字细化失败也不丢弃音轨：优先复用已有的字词时间，失败词组在已有起止时间内匀速扫亮；播放时不额外显示“估算”提示。完整歌词采用局部高亮回退时记 soft fail；仍有歌词行无法定位或全曲没有可用字幕时记 hard fail，不显示“已准备”。可用字幕、原始字词和修复诊断继续保留，不丢弃已有工作。这些回退不计为逐字验收通过；独立音频回归中的 ASR 验证仍单独运行。

未对齐唱段先直接重试原歌词：根据该段音频选择对齐语言，不强制沿用整首歌的语言标签，以支持外语副歌或旁白；这里只做语言分类，不生成转录。普通点歌与音频验收都只在缺句、严重塌缩或时间冲突时调用本地 ASR 定位，再对齐原歌词；已有完整有效时间轴的歌曲不触发识别。全块识别漏掉的唱段允许在独立邻句限定的范围内再次定位，仍受同一恢复预算约束。整份歌词仍缺行时，从同次检索中逐个尝试已通过身份及完整性筛选的其他完整文本，相同正文只试一次；不拼接或删掉对不上的行。失败来源的原文、字幕及对齐诊断保存在 `lyric-source-attempts/`，所有候选失败仍报错。

已证实偏移的起点不能被旧回退结果重新带回。局部重定位仍失败时，播放流程允许把两个经独立声学核对的起点之间、内部边界不确定的最小词组合并扫亮。句尾没有下一个起点时，必须另行核对两种音频视图和三次上下文预测的文本末端，采用一致区间的最晚末端；字幕延长显示的尾巴不参与核对，也不将该末端当成演唱停止时间。不跨过另一个已确认的起点，不改动其余歌词，也不把词组内部当成实测逐字时间。该回退保留在 `timing_review.estimated_spans`，统计为 `timing_group_fallback`；缺少任一端的可靠定位时仍失败。严格逐字验收不启用这条播放回退。

新视频下载和音频补画面最多选择 720p，继续单独获取最佳可用音频。已有来源缓存直接复用；旧成品按已记录格式恢复时仍须核对原始音频，避免换源后与保留音轨错位。

播放前同时等待当前段的三条音轨解码和视频首帧可用；视频失败或超时不会提前启动演唱时钟。切歌后，旧视频的加载事件不能放行新歌。

设置 `KARAOKE_PREPARATION_CONCURRENCY=none` 后不限制在途歌曲数，所有已点歌曲进入阶段流水：下载、分离、识别／对齐、音轨封装和视频编码各有共享工位，不同阶段可同时工作。尚未拿到工位的任务按当前待唱歌曲、歌单顺序排序；调整顺序不打断已开始的步骤。等待任务显示等待状态，不伪造进度。共享缓存仍受原有容量限制。

普通点歌先获取最佳音频。下载器写出来源元数据时即启动歌词查询，不等传输或封面完成；明确歌名、歌手时，描述分析与多源歌词查询并行，最后仍汇总完整证据。音频完成后即可解码和分离，同源视频在另一分支下载；新下载返回的媒体信息直接用于取视频，不重复解析同一网页。已有完整媒体继续复用。

缺少歌名或歌手时，先按视频 ID 读取 YouTube Music 的结构化信息和歌词；不要求先判断原唱或翻唱。平台信息仍不足才让模型补字段，简介歌词作为独立候选保留。歌词网络响应按实际请求缓存；真实时长与预估不同只重新选择候选，已读取的正文不重复下载。来源的登录要求和限流仍在真正联网时生效，不能从共享退避记录继承另一首歌的身份。

原采样率音频仅完整解码一次，保存带来源与内容哈希的临时 float64 PCM，供两次母版封装复用；模型输入格式保持不变。首轮人声就绪后，主唱分离、两轨母版封装和对齐用重采样各自开始；三轨封装只等待所需音轨，对齐只等待歌词与重采样人声。最终 MP3 最多两路并行编码、完整解码检查；任一轨削波时仍整组统一调整增益。中间两轨不编码试听 MP3，也不生成普通点歌用不到的 ASR MP3。

网页只生成使用中的三条 MP3 分轨，不额外生成合成的 `karaoke.mp3`；共同增益仍计算原音乐、各分轨与 KTV 混音的峰值。独立封装工具默认仍可导出合成试听文件。同源补画面直接用于字幕渲染，不再把原音频装入中间视频再拆掉；仍核对来源和时长，最终混入已验证的分轨并完整解码成品。

各对齐阶段只追踪自身代码及依赖，末端修复变化不会让上游识别缓存失效。同一进程内模型哈希只计算一次。个别歌词行被模型改写时，先在已定位邻句之间重试原文；局部修复不足时才扩大到整个块，并保留已得到的有效结果。

最终字幕和源视频齐备即可渲染画面，与剩余音频封装并行；共同增益确定后合入音频，视频流直接复制，不二次压缩。最终 MV 仍须通过全长解码与时长检查。所有必需产物校验结束后才显示已准备，iPad 仍播放预先完成的字幕视频。

已取得的同源歌名、歌手、语言和时长保存在任务数据库，重建任务时立即继承；媒体被 LRU 回收也不退回“新点的歌”。已校验的元数据模型结果及输入指纹一并保留，匹配时直接复用；下载地址过期需刷新时，不把它当作歌曲身份丢失。

- SQLite 保留歌单和任务，页面通过 SSE 接收更新与断线重连快照，不轮询。
- 正常关闭服务时暂停歌曲；重新打开网页可能需要点击启用声音。
- 移除歌单项不会立即删除媒体；它会解除该歌曲的缓存保护。已提交的预处理继续完成，缓存随后可按 LRU 回收，失败项可以重试。
- 「首次准备」表示完整可播放文件尚不存在；历史实验的元数据、封面仍可以展示，但不会冒充现成伴奏。
- 同一来源有多次任务时，曲库优先展示文件完整的成品，其次展示仍可补回视频的成品；较新的预下载、失败或处理中记录不会盖掉它们。移出已点歌只解除缓存保护，回收仍按共享容量和最近使用时间进行。
- 自动歌词可能识别错误，网页会提示；预处理失败与正在等待会分别显示。
- 当前是本地单房间 MVP，浏览器保留当前段及随后约 24 秒的三轨解码音频（每段 8 秒）。不是在线多人隔离服务，也暂不包含麦克风效果器和评分。

### 平板播放

播放页按需读取现有母版的 8 秒片段，统一应用成品的防削波增益，以 24-bit FLAC 传输；保留原采样率与声道，不重跑分离、歌词、对齐或视频渲染。服务器只做短段读取和 CPU 压缩，不调用 GPU。MP3 试听下载仍保留。

客户端先加载当前段即可开唱，后台持续下载到整首完成，不在 24 秒处停止。已下载的压缩音频可供定位和重唱复用；只将当前段及随后约 24 秒解码，控制内存占用。临时网络错误自动退避重试，切歌会取消旧下载。三轨按同一个 AudioContext 时钟调度，段边界带有重采样余量，播放时裁掉重叠部分。一轨仍未到齐时先播完已有音频，再一起等待，本机时钟冻结在共同边界，加载完成后恢复。视频保持原生速度，缓冲状态短暂下降但画面仍推进时不打断声音；实际停滞或明显失步时才暂停并重新就绪。提前下载可吸收网络波动，但不能保证持续断网或设备解码异常时仍然流畅。
