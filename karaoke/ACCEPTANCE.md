# 从选定视频到开唱：验收标准 v0.5

这些数字是拟定的第一版目标，不是已测性能，也不代表当前算法已经达到。
目标固定后再评估后续版本；变更目标必须记录原因，不能为了通过当前结果降低门槛。

## 第一版产品范围

按用户确认的简化方案：提供搜索框，可前往 YouTube / B 站搜索、预览，用户选择具体视频后确认使用。第一版可通过跳转平台搜索页并粘贴视频链接完成，不要求先做聚合搜索或语音点歌。

用户确认视频后并行执行：

1. yt-dlp 完整下载该视频的媒体，解码并送入无神经网络的音频处理程序，完成整首人声/伴奏分离。第一版不做边下载边处理、首段抢先播放或增量分块调度。
2. 获取标题、描述、可用字幕等上下文，通过 Codex SDK 接入的 Codex agent 整理歌名、歌手、语言、版本与候选歌词。Codex 必须收到实际内容，或显式配备检索/读取工具；单独传 URL 不等于模型读过视频。元数据不确定的字段留空，歌词保留来源，不把模型凭记忆补写的文本当成已核实歌词。
3. 在预处理阶段将整首歌词与选定录音对齐，生成固定的逐句起止时间戳。假设视频画面没有歌词、没有可用字幕时间轴；核心对齐只接收纯文本歌词与干声。完整伴奏与同步歌词就绪后再开唱，并缓存整个歌曲包。

播放阶段依据歌曲播放位置读取既有歌词时间轴，不分析用户的麦克风歌声，不按用户唱得快慢动态调整歌词或伴奏。预处理歌词对齐仍是核心算法；演唱时实时跟踪不属于第一版。

允许元数据/歌词环节使用 LLM API；无神经网络的限制继续适用于音频分离和信号处理。LLM 不在播放回调中运行，其延迟、失败率和费用单独记录。歌名等非关键展示字段不阻塞开唱，歌词是关键依赖。相同视频的元数据和歌词同样缓存。

研究例外（2026-09-18）：用户已明确允许预训练神经网络作为效果对照，之后再决定最终方案。此授权适用于独立的 NN 对照实验，不表示最终产品架构已经改为 NN；质量和计时口径保持不变。

同日后续授权：用户对字幕阶段明确回复“允许，先把字幕效果做好”，允许使用现成语音模型做歌词对齐基线。仍保留原有歌词来源、录音版本一致性和时间戳质量验收要求。

v0.5 约定：去掉烧录歌词和现成时间轴的假设。文字可以来自已核实的歌词来源，但 OCR 时间、人工字幕时间、其他版本的 LRC 时间不得作为核心对齐输入。已有人工作为评测的时间标签需与推理输入隔离。历史混合基线可保留，不能标成纯音频通过；音频模型的单调时间轴也不等于准确时间轴。

视觉要求：字幕背景透明，以字体、字距、位置和轻微局部阴影保证阅读；不再添加不透明底条。样式需要在中、日、英文以及明亮、深色、复杂画面上分别检查。允许不同字体方向，不将某个歌手的 MV 当成唯一模板。设计稿和动效样张不计作歌词对齐验收。

范围变更记录：v0.2 删除自动决定歌曲/版本及语音识别要求，将计时起点从提交歌名改为确认视频。v0.3 按用户要求接受完整预处理的等待，移除增量处理要求，明确保留预处理歌词对齐、排除演唱时实时跟踪；伴奏、歌词和时间戳的质量标准不变。此前关于取消全部歌词对齐的口头理解已被用户纠正，不作为产品要求。

## 1. 总指标和计时边界

- t0：用户确认“使用这个视频”或提交具体视频 URL。本地样本则从确认处理该文件开始。搜索、预览和用户选择耗时另记，不计入本版本 T_ready。
- T_ready：从 t0 到整首正确版本的伴奏、固定同步歌词和播放器均已准备好，可以立即播放。用户随后自行等待才按播放的时间不计入；另测按播放到首音的延迟。
- 只出现页面、原唱开始播放、低质量临时伴奏或无同步歌词的播放，均不算完整达标。可以另外报告降级可播放时间。
- T_vocal：第一句可演唱人声对应的时刻。原版前奏长度单独报告；不能偷偷裁掉前奏来改善 T_ready/T_vocal。
- 报告整首播放的卡顿与音画同步。不能靠只准备第一句得到短 T_ready；此版本在开唱前完成整首预处理。
- 不得用另一首歌、翻唱、演唱会或录音室版本替换选定版本。

| 缓存状态 | T_ready P50 目标 | T_ready P95 目标 |
| --- | ---: | ---: |
| 本地已有合格歌曲包 | ≤0.5 s | ≤1 s |
| 本地只有原始媒体，歌词/伴奏均未准备 | 记录整首准备耗时，暂不设硬门槛 | 先实测再确定 |
| 已选定网上视频，首次使用且无本地缓存 | 记录完整下载与整首准备耗时，暂不设硬门槛 | 先实测再确定 |

端到端准备耗时包含确认视频之后的冷启动、URL 解析、必要的元数据/歌词检索及 Codex 调用、完整下载、整首分离/歌词对齐和播放器准备。新建开发环境、安装工具不计入常规请求，但按请求需要的初始化不得排除。按播放后的首帧/首音延迟另报。
阶段可以并行，总时间使用实际事件时间戳，不相加独立阶段的 P95。

## 2. 分环节门槛

| 环节 | 正确性/质量要求 | 延迟/效率目标 |
| --- | --- | --- |
| 搜索入口与视频选择 | 能搜索/预览并提交具体视频链接，所下载视频与用户选择 100% 一致；保留 URL、视频 ID、标题、频道和时长。自动识曲、语音点歌与聚合搜索不在本版门槛中。 | 平台搜索和用户选择耗时另报；本地缓存查询 ≤50 ms。 |
| LLM 整理歌曲信息 | 歌名、歌手、语言、版本来自可追溯的标题/描述/字幕等材料；不确定时不捏造。显示名称不改变已选媒体身份。 | 与媒体下载并行；非关键展示字段不阻塞播放；记录 API 耗时、失败率和费用。 |
| 获取媒体 | 完整文件解码通过；不能只下载预览而标作完整歌曲。保留原始时间轴。 | 记录完整下载耗时；开唱前媒体已在本地，不要求首段抢先播放。 |
| 解码/音轨提取 | 选对音轨，采样率转换显式记录，无非有限值；输出时间轴与源一致。 | 启动进程并解码本地 10 s 音频 ≤0.3 s P95。 |
| 人声削弱/分离 | 使用下面的客观和盲听双门槛，不能把输出静音作为消原唱成功。 | 记录整首处理耗时，RTF ≤0.05 为优化目标；不设流式前瞻或分块处理门槛。 |
| 歌词取得/整理 | 允许 Codex 根据已获取的资料或显式检索工具整理候选歌词，保留文本来源。中文/日文归一化字错率 CER ≤2%，每首单独计算；整句漏掉、凭空添加或错误重复均为失败。来源字幕需人工核实，不能直接套用另一录音版本的段落顺序。 | 与下载并行，记录全曲歌词取得耗时，不再要求首两句在 3 s 内返回。 |
| 预处理歌词对齐 | 生成整首固定时间轴。逐句起点绝对误差 P50 ≤100 ms、P95 ≤250 ms、最大 ≤500 ms；句尾 P95 ≤300 ms。前、中、后均满足，不能用整体平均掩盖后半段漂移。 | 记录整首对齐耗时；在播放前完成，不做演唱时实时对齐，不设首段 1 s 或增量门槛。 |
| 播放/切换 | 整首 0 卡顿；音画偏差绝对值 P95 ≤80 ms；原唱/伴奏切换不跳拍、无可闻爆音。 | 播放器已备好媒体后的首音 ≤200 ms P95；切换生效 ≤100 ms P95。 |
| 缓存 | 同一源内容+算法/配置版本正确命中；不会拿旧歌词配新音轨；再次点歌不重新下载/分离。 | 使用总表中的已缓存目标；记录命中率及磁盘占用。 |

RTF = 处理耗时 / 音频时长。它是吞吐量指标，不是首音延迟。
没有同步歌词只能算降级结果，不能用歌词页面或均匀分字模拟通过对齐门槛。
逐字／逐词高亮已进入迭代，使用独立的[起唱高亮验收协议](docs/word-onset-metrics.md)：比较实际亮帧与独立人工发音起点，拟定 Hit@50 ms ≥90%、Hit@100 ms ≥98%、严重错误率 ≤1%、覆盖率 100%。这些是新增工程目标，尚未测得通过；逐句通过不等于逐字通过。

当前已有[按歌声发音细化的高亮候选](experiments/word-timing-v001/README.md)。字符覆盖、时间单调和回退统计已检查，仍未完成独立的逐字起唱标注，不能将“能逐字点亮”或模型置信度称作准确率。

新增[英文起点回归实验](experiments/word-onset-v001/README.md)：6 首、1,876 个人工词起点，时间戳 PCO@50 ms 28.3% → 54.6%，PCO@100 ms 51.4% → 80.0%。用于选参的 3 首与冻结后评分的另外 3 首分别报告，保留退步和失败；该结果未通过上述门槛，不等于当前五首开发 MV 或最终亮帧已验收。

## 3. 分离质量：两组证据

新增的主唱／伴唱细分任务另见[评测口径](docs/lead-backing-metrics.md)：有真实声部时逐轨报告 SI-SDR、SI-SIR 和固定增益重建误差，并单列重叠演唱；当前四首没有真实主唱／伴唱参考，因此三轨重合误差小不代表细分质量通过。原双轨门槛不直接当作三轨纯度门槛。

### 音轨交付与完整性

用户要求每首完整输出人声与伴奏，分别试听两侧的串音。最新澄清允许少量残留；五月天现场版少量观众合唱已经明确可接受。保住声音的完整、自然是当前试听目标，没有据此虚构新的数值评分。

- 两轨母版保留原录音解码后的采样率、声道和完整帧数，无独立音量归一化；人声轨可保留原有混响，不附加去混响要求。
- 使用 64 位浮点 WAV 保存模型输出，用相减生成补轨；不再为逐比特相加一致而重分配样本，也不因浮点相消的末位差异终止封装。实际文件读回后的重合误差仅作诊断。
- 校验源文件与各产物哈希、完整帧数、采样率、声道、有限数值；源 PCM 哈希用于核对来源身份，不用于要求三轨相加后的哈希一致。MP3 仍需全长解码、检查尾部填充并使用共同防削波增益。
- 普通准备和固定样本音频验收都采用上述完整性检查。历史失败记录保留，新版本必须实际跑完产物校验才能计为通过；不会把旧的封装失败直接改为成功。
- MP3 是公共增益的试听版本。母版重合误差小不证明人声和乐器归属正确，各轨纯度仍需分开试听。

### 有真实参考分轨的测试集

- 以未参与调参的真实人声 V 和伴奏 B 混合得到 X；保留真实立体声、混响与相对电平。
- 输出 Y 与 B 使用相同预定采样率和固定输入增益；不允许在评分时为每个结果拟合音量或时间平移。
- 重建分数 `10 log10(sum(B²) / sum((Y-B)²))` 每首 ≥12 dB，同时相对未经处理的 X 提升 ≥6 dB。这是初始工程门槛，不是通用听感标准。
- 对能把混合输入算出的固定掩码分别施加于 V、B 的算法，另报告人声衰减和伴奏破坏；不能在 V、B 上分别重新估计掩码。希望整段人声衰减 ≥15 dB，有人声的 1 s 窗中至少 95% ≥10 dB。
- 不支持这种分解的算法不可虚构单独人声衰减，改以总重建误差和盲听确认。
- 合成音仅用于验证机制和数值正确性，不能替代真实分轨测试集。

### 当前四首真实歌曲的盲听

当前只有混音原始输入，没有经过核实的真实参考伴奏，不能报告真实的 SDR、漏字率或字幕误差。

- 每首至少覆盖主歌、副歌、无主唱/间奏；现场版另覆盖观众声；片段提前选定并冻结，不能按输出好坏挑。
- 随机隐藏算法名字，比较原始、消中置基线和候选；配对使用共同增益，记录所有增益，不用分别提升输出音量掩盖破坏。
- 主唱残留、伴奏完整性、处理伪影、实际可唱性分别 1–5 分（5 最好）。每首每项平均 ≥4，且没有片段低于 3；至少两位独立听者才形成正式结论。
- 全曲检查不能出现伴奏主旋律长段消失、明显水声/抽吸或削波；长度、声道与时间轴必须保持。
- 当前阶段可以由用户先做一轮试听筛选，标记为初评，不包装成正式盲听结果。
- 候选比基线好的结论要求在达到相同最低主唱削弱门槛后，伴奏完整性或伪影更好。保留更多原唱而获得更好伴奏，不自动算进步。

## 4. 测量和防止过拟合

- 四首歌属于开发集，每首单列结果，任何一首失败不能用四首平均掩盖；不得使用歌名分支、手写某首时间戳或每首特制参数通过通用算法验收。
- 歌词正文及逐句时间由人工建立独立参考，记录标注容差；算法自动生成的歌词或时间不能给自身当参考答案。
- 首轮每首每种缓存状态至少重复 10 次，报告所有结果、中位数和最大值；当前四首不足以宣称对任意歌曲有效。
- 推广到 P95 SLO 验收时，使用至少 30 首未参与调参的歌曲、每种状态至少 100 次请求，并分开语言、录音室/现场与输入形式。
- 固定并记录硬件、系统、算法版本、并发数、网络吞吐/RTT、缓存状态和计时口径。未经实际控制的网络不能标成理想固定带宽。
- 时间日志包含 search_submitted / source_selected（t0）/ metadata_ready / codex_started / codex_finished / download_finished / separation_finished / lyrics_ready / alignment_finished / song_ready / play_requested / playback_started 等单调时钟事件。
- 测试中的超时、无源、缺词、低质量降级均计入失败率，不能从延迟统计中删除而不报告。无效用户请求与有效歌曲请求另分组。
- 成功率门槛：固定四首全部通过；拓展测试集满足全部质量和时间门槛的请求比例 ≥95%。
- 原非 NN 候选不调用神经网络，不使用其预生成分离结果冒充本算法输出；经明确授权的 NN 效果对照单独记录，不视为产品架构约束自动变更。元数据/歌词整理明确允许 LLM API。依赖、算法、提示词及资料来源需记录。在线来源内部技术不可声称受本项目控制。

## 5. 当前证据

`experiments/heuristic-v001/report.json` 仅包括固定位置 25 s 片段的本地解码/算法吞吐与人工合成音的机制测试。

第一批实测已补充至 `experiments/iteration-001.md`：

- 分离实验 `separation-v002` 至 `v005` 使用真实分轨的校准和留出片段，共 48 个新配置；四轮冻结的候选均未通过全部客观门槛。
- 对齐实验 `alignment-v001` 至 `v004` 使用人工标注的英文歌曲；最新高斯发音模板只在校准词段拟合，推理不读取参照时间。留出歌曲仍未达到逐句时间误差门槛。
- 四首产品样本已导出完整原曲与三个分离候选，位于 `experiments/listening-v002`。用户对 Lemon 固定片段的排序为 A > C > B，但指出 A、C 均未去掉原唱，B 伴奏损伤大；A 只作为低损伤对照，仍没有通过验收的默认版本。尚需多片段正式盲听。
- 5 项实现行为测试通过，但不能替代音质与歌词时间质量测试。

第二轮见 `experiments/iteration-002.md`：新增 16 个空间滤波组合。只加强中间声道的候选均未满足研究筛选条件；同时压制侧声道的新候选 D 在 12 段新留出音频上人声衰减增加、伴奏保真和总重建均下降，全部客观门槛仍为 0/12。A 保留为低损伤对照，D 仅用于诊断试听；没有通过降低目标选出默认算法。

第三轮见 `experiments/iteration-003.md`：用户授权预训练 NN 效果对照。六段既有 MUSDB test 诊断片段上，F（Mel-Band RoFormer）与 G（Sony MIMO）均通过两项重建门槛，F 中位数 18.22 dB、最差 17.31 dB。用户在 Lemon 片段上反馈 F > E，故 F 成为下一轮研究基线。尚无正式多听者、多片段音质验收。完整 Lemon 的 F 分离用时 95.49 秒，RTF 0.348，仍未达到 0.05 的速度优化目标；这也不是端到端准备时间。歌词对齐本轮未迭代。
