# 从选定视频到开唱：验收标准

以下数字是保留的工程目标，不是已测性能，也不代表当前算法已经达到。
目标固定后再评估后续版本；变更目标必须记录原因，不能为了通过当前结果降低门槛。

## 产品范围

用户搜索、预览并选定具体视频；服务完整下载媒体，使用神经网络分离与歌词对齐完成整首预处理，必要时用 ASR 定位；严格音频验收另检查识别覆盖，再交付音轨、字幕和视频。音乐保留原录音，不生成替代歌曲。正式入口、模型准备与网页行为分别见 [README](../README.md)、[SETUP](../SETUP.md) 和 [APP](APP.md)。

普通点歌优先检索已发表歌词，保留来源身份、正文与诊断。模型可从已获取的元数据和简介中提取信息，不能凭记忆编造歌词；关键正文无法核实时明确失败。显示名称不改变选定录音的身份。

核心对齐只依赖音频与歌词文本，不读取画面 OCR、其他录音的 LRC 时间或人工评测标签。对齐在预处理阶段完成；播放时使用固定时间轴，不分析麦克风歌声或追踪演唱速度。模型调用不在播放回调中执行。

字幕透明底、清楚可读、琥珀色高亮，保留当前句和下一句预读，换句直接切换。预读不得提前点亮；不使用整体时间偏移或均分字词来伪造起音精度。视觉、起音和分离质量分别验收，不能互相替代。

## 1. 总指标和计时边界

- t0：用户确认“使用这个视频”或提交具体视频 URL。本地样本则从确认处理该文件开始。搜索、预览和用户选择耗时另记，不计入本版本 T_ready。
- T_ready：从 t0 到整首正确版本的伴奏、固定同步歌词和播放器均已准备好，可以立即播放。用户随后自行等待才按播放的时间不计入；另测按播放到首音的延迟。
- 只出现页面、原唱开始播放、低质量临时伴奏或无同步歌词的播放，均不算完整达标。可以另外报告降级可播放时间。
- T_vocal：第一句可演唱人声对应的时刻。原版前奏长度单独报告；不能偷偷裁掉前奏来改善 T_ready/T_vocal。
- 报告整首播放的卡顿与音画同步。不能靠只准备第一句得到短 T_ready；此版本在开唱前完成整首预处理。
- 不得用另一首歌、翻唱、演唱会或录音室版本替换选定版本。

| 缓存状态 | T_ready P50 目标 | T_ready P95 目标 |
| --- | ---: | ---: |
| 本地已有合格歌曲包 | ≤0.5 s | ≤1 s |
| 本地只有原始媒体，歌词/伴奏均未准备 | 记录整首准备耗时，暂不设硬门槛 | 先实测再确定 |
| 已选定网上视频，首次使用且无本地缓存 | 记录完整下载与整首准备耗时，暂不设硬门槛 | 先实测再确定 |

端到端准备耗时包含确认视频之后的冷启动、URL 解析、必要的元数据/歌词检索及模型调用、完整下载、整首分离/歌词对齐和播放器准备。新建开发环境、安装工具不计入常规请求，但按请求需要的初始化不得排除。按播放后的首帧/首音延迟另报。
阶段可以并行，总时间使用实际事件时间戳，不相加独立阶段的 P95。

## 2. 分环节门槛

| 环节 | 正确性/质量要求 | 延迟/效率目标 |
| --- | --- | --- |
| 搜索入口与视频选择 | 能搜索/预览并提交具体视频链接，所下载视频与用户选择 100% 一致；保留 URL、视频 ID、标题、频道和时长。自动识曲、语音点歌与聚合搜索不在本版门槛中。 | 平台搜索和用户选择耗时另报；本地缓存查询 ≤50 ms。 |
| LLM 整理歌曲信息 | 歌名、歌手、语言、版本来自可追溯的标题/描述/字幕等材料；不确定时不捏造。显示名称不改变已选媒体身份。 | 与媒体下载并行；非关键展示字段不阻塞播放；记录 API 耗时、失败率和费用。 |
| 获取媒体 | 完整文件解码通过；不能只下载预览而标作完整歌曲。保留原始时间轴。 | 记录完整下载耗时；开唱前媒体已在本地，不要求首段抢先播放。 |
| 解码/音轨提取 | 选对音轨，采样率转换显式记录，无非有限值；输出时间轴与源一致。 | 启动进程并解码本地 10 s 音频 ≤0.3 s P95。 |
| 人声削弱/分离 | 使用下面的客观和盲听双门槛，不能把输出静音作为消原唱成功。 | 记录整首处理耗时，RTF ≤0.05 为优化目标；不设流式前瞻或分块处理门槛。 |
| 歌词取得/整理 | 允许模型根据已获取的资料或显式检索工具整理候选歌词，保留文本来源。中文/日文归一化字错率 CER ≤2%，每首单独计算；整句漏掉、凭空添加或错误重复均为失败。来源字幕需人工核实，不能直接套用另一录音版本的段落顺序。 | 与下载并行，记录全曲歌词取得耗时，不再要求首两句在 3 s 内返回。 |
| 预处理歌词对齐 | 生成整首固定时间轴。逐句起点绝对误差 P50 ≤100 ms、P95 ≤250 ms、最大 ≤500 ms；句尾 P95 ≤300 ms。前、中、后均满足，不能用整体平均掩盖后半段漂移。 | 记录整首对齐耗时；在播放前完成，不做演唱时实时对齐，不设首段 1 s 或增量门槛。 |
| 播放/切换 | 整首 0 卡顿；音画偏差绝对值 P95 ≤80 ms；原唱/伴奏切换不跳拍、无可闻爆音。 | 播放器已备好媒体后的首音 ≤200 ms P95；切换生效 ≤100 ms P95。 |
| 缓存 | 同一源内容+算法/配置版本正确命中；不会拿旧歌词配新音轨；再次点歌不重新下载/分离。 | 使用总表中的已缓存目标；记录命中率及磁盘占用。 |

RTF = 处理耗时 / 音频时长。它是吞吐量指标，不是首音延迟。
没有同步歌词只能算降级结果，不能用歌词页面或均匀分字模拟通过对齐门槛。
逐字／逐词高亮已进入迭代，使用独立的[起唱高亮验收协议](docs/word-onset-metrics.md)：比较实际亮帧与独立人工发音起点，拟定 Hit@50 ms ≥90%、Hit@100 ms ≥98%、严重错误率 ≤1%、覆盖率 100%。这些是新增工程目标，尚未测得通过；逐句通过不等于逐字通过。

历史实验的私有试听页和数据未随仓库提供，不能作为可复现的通过证明。[起唱高亮验收协议](docs/word-onset-metrics.md)保留测量口径与已知局限。

## 3. 分离质量：两组证据

主唱／伴唱细分任务另见[评测口径](docs/lead-backing-metrics.md)：有真实声部时逐轨报告 SI-SDR、SI-SIR 和固定增益重建误差，并单列重叠演唱。只有混音、没有真实声部参考时，三轨重合误差小不代表细分质量通过。原双轨门槛不直接当作三轨纯度门槛。

### 音轨交付与完整性

每首完整输出人声与伴奏，分别试听两侧的串音。允许少量自然残留，以保住声音的完整和自然；不能靠破坏大量伴奏换取更少残留，也不能据此降低下面的数值目标。

- 两轨母版保留原录音解码后的采样率、声道和完整帧数，无独立音量归一化；人声轨可保留原有混响，不附加去混响要求。
- 计算阶段使用 64 位浮点 WAV，用相减生成补轨；不再为逐比特相加一致而重分配样本，也不因浮点相消的末位差异终止封装。普通播放以共同增益 24 位 FLAC 保存底轨（背景音乐＋伴唱）和主唱两轨，完整比较编码前后的量化误差，且不得改变送给播放器的 PCM。计算阶段重合误差仅作诊断；严格音频验收可继续保存 float64 WAV。
- 校验源文件与各产物哈希、完整帧数、采样率、声道、有限数值；源 PCM 哈希用于核对来源身份，不用于要求三轨相加后的哈希一致。MP3 仍需全长解码、检查尾部填充并使用共同防削波增益。
- 普通准备和固定样本音频验收都采用上述完整性检查。历史失败记录保留，新版本必须实际跑完产物校验才能计为通过；不会把旧的封装失败直接改为成功。
- MP3 是公共增益的试听版本。母版重合误差小不证明人声和乐器归属正确，各轨纯度仍需分开试听。

### 有真实参考分轨的测试集

- 以未参与调参的真实人声 V 和伴奏 B 混合得到 X；保留真实立体声、混响与相对电平。
- 输出 Y 与 B 使用相同预定采样率和固定输入增益；不允许在评分时为每个结果拟合音量或时间平移。
- 重建分数 `10 log10(sum(B²) / sum((Y-B)²))` 每首 ≥12 dB，同时相对未经处理的 X 提升 ≥6 dB。这是初始工程门槛，不是通用听感标准。
- 对能把混合输入算出的固定掩码分别施加于 V、B 的算法，另报告人声衰减和伴奏破坏；不能在 V、B 上分别重新估计掩码。希望整段人声衰减 ≥15 dB，有人声的 1 s 窗中至少 95% ≥10 dB。
- 不支持这种分解的算法不可虚构单独人声衰减，改以总重建误差和盲听确认。
- 合成音仅用于验证机制和数值正确性，不能替代真实分轨测试集。

### 无独立分轨参考的真实歌曲盲听

只有混音原始输入、没有经过核实的真实参考伴奏时，不能报告真实的 SDR；缺少独立正文或起音标注时也不能报告漏字率或字幕误差。

- 每首至少覆盖主歌、副歌、无主唱/间奏；现场版另覆盖观众声；片段提前选定并冻结，不能按输出好坏挑。
- 随机隐藏算法名字，比较原始、消中置基线和候选；配对使用共同增益，记录所有增益，不用分别提升输出音量掩盖破坏。
- 主唱残留、伴奏完整性、处理伪影、实际可唱性分别 1–5 分（5 最好）。每首每项平均 ≥4，且没有片段低于 3；至少两位独立听者才形成正式结论。
- 全曲检查不能出现伴奏主旋律长段消失、明显水声/抽吸或削波；长度、声道与时间轴必须保持。
- 当前阶段可以由用户先做一轮试听筛选，标记为初评，不包装成正式盲听结果。
- 候选比基线好的结论要求在达到相同最低主唱削弱门槛后，伴奏完整性或伪影更好。保留更多原唱而获得更好伴奏，不自动算进步。

## 4. 测量和防止过拟合

- 早期四首样本属于开发集，每首单列结果，任何一首失败不能用平均值掩盖；不得使用歌名分支、手写某首时间戳或每首特制参数通过通用算法验收。
- 歌词正文及逐句时间由人工建立独立参考，记录标注容差；算法自动生成的歌词或时间不能给自身当参考答案。
- 首轮每首每种缓存状态至少重复 10 次，报告所有结果、中位数和最大值；早期四首样本不足以宣称对任意歌曲有效。
- 推广到 P95 SLO 验收时，使用至少 30 首未参与调参的歌曲、每种状态至少 100 次请求，并分开语言、录音室/现场与输入形式。
- 固定并记录硬件、系统、算法版本、并发数、网络吞吐/RTT、缓存状态和计时口径。未经实际控制的网络不能标成理想固定带宽。
- 时间日志包含 search_submitted / source_selected（t0）/ metadata_ready / model_started / model_finished / download_finished / separation_finished / lyrics_ready / alignment_finished / song_ready / play_requested / playback_started 等单调时钟事件。
- 测试中的超时、无源、缺词、低质量降级均计入失败率，不能从延迟统计中删除而不报告。无效用户请求与有效歌曲请求另分组。
- 成功率门槛：固定四首全部通过；拓展测试集满足全部质量和时间门槛的请求比例 ≥95%。
- 每个候选如实记录是否使用神经网络、预训练模型、在线 API 或预生成结果。记录依赖、算法、提示词及资料来源；不能把固定代码流程称为“没有神经网络”。在线来源内部技术不受本项目控制。

## 5. 验收记录

每次验收记录代码和模型版本、硬件、数据集来源、冷／热缓存状态、全部失败及原始测量。开发歌曲与独立留出集分别报告，不把历史开发样本重新标成盲测。

[行为测试](../README.md#验证)验证程序行为；[自动质量工具](docs/automatic-quality.md)只有在提供独立参考时才计算准确率。两者都不能单独证明本文件的全部音质、起音和端到端性能目标已通过。歌曲、歌词、人工标注及实验产物不随仓库分发，公开报告需另外核对数据授权并给出可复现输入。
